# 流程控制规范模块

> **模块定位**：定义全流程的执行流程和循环逻辑，所有阶段（S1-S6）共用。本模块定义"怎么做"（执行流程），横切机制.md 保留"是什么"（机制概述）。

> **与横切机制的边界**：横切机制.md 机制6/7/8 改为概述+引用"详见流程控制规范.md"。本模块是流程控制逻辑的唯一真实来源。

---

## 一、最高宗旨（贯穿全流程，任何步骤都不得违背）

> 以下4条是全流程最高优先级规则，等同于宪法。

1. **AI 是辅助方，不是决策方。** AI 负责：搜索资料、检索文献、发现并比较可行方法、执行计算与编程、整理与可视化、按规范排版呈现；**不负责替我们做最终选择**。

2. **凡涉及 "选哪种模型 / 用哪条思路 / 取哪组参数 / 采纳哪个结论" 等决策点，AI 必须停下来，列出可选项 + 各自优劣 + 适用条件，交由我（用户）拍板后再继续。**

3. **严禁编造。** 文献、数据、公式、图表、计算结果一律不得虚构；找不到就如实说明 "未检索到 / 不确定"，并给出替代检索方向。

4. **可追溯。** 所有结论、数据、图表都要能追溯到来源（文献链接 / 原始数据 / 代码运行结果），便于我们复核。

> **暂停规则的优先级等同于最高宗旨**：违反暂停规则等同于违反"AI是辅助方不是决策方"。

## 二、步骤执行模式（9动作强制序列）

> 微循环保留独立检查和修改循环，但**不产出独立隔离检查结论文件**，
> 隔离子Agent直接将检查结论反馈给产者，避免格式折腾浪费时间。
> 微循环验证.py脚本已移除。

```
每步执行流程（9动作）：

1. 读取验证：读取上一步产物 + 启动必读文件（索引导航.md + 产物规范.md）
   ├─ 【暂停确认】检查用户是否已回复"继续"
   └─ 【读取验证】读取上一步产物 + 输出三要素摘要

2. 执行：按步骤内容产出

3. 写入产物文件：将产物写入独立文件（含 ## 变更说明），版本号 v1.0
   - 文字类步骤产出 .md 文件
   - 代码类步骤产出 .py 文件 + 运行结果数据文件

4. 独立检查（**审查方物理隔离 + 先重读再检查**，杜绝"自己查自己"）：
   4a. 主AI初检（快速筛查，仅作辅助参考，非终审）：
       - 重新读取：用 Read 工具重新读取刚写入的产物 MD 文件
       - ⚠️ 强制要求：不能使用产出时的上下文！必须重新读取文件！
       - 按检查模板库.md三层标准做初步检查（通用+分类+专属）
       - 产出初检草稿（不写入最终报告，仅供自己参考）
   4b. **spawn 隔离子Agent 做终审（硬性门禁，每步必做）**：
       - **调用方式**：使用 Agent 工具，`subagent_type="general_purpose_task"`，每次**全新 spawn**，
         不得复用任何产者上下文
       - ⚠️ **不可用 Explore 类型**：Explore 是只读 Agent，无法写入隔离检查反馈，会导致反复 spawn 失败
       - **审查范围白名单**：本轮产物文件 + 赛题原始文件 + 允许的外部权威资料（子Agent仅允许读取这些文件）
       - **禁读黑名单**：产者思路/上轮报告/内部模板/主AI初检草稿
       - **子Agent任务**：以"最挑剔的国一评委"视角冷读产物，
         按检查模板库.md 三层标准逐项检查，每项给出具体证据
       - **子Agent输出方式**：直接返回检查结论（【独立判决】+ 问题清单 + 优化建议），
         不写入独立  文件
       - ⚠️ **独立性铁律**：主AI不得替子Agent组织检查内容，
         子Agent必须独立得出结论，结论不一致以隔离子Agent为准
   4c. **比对与结论**：
       - 主AI初检 vs 隔离子Agent终审 —— 结论不一致以隔离子Agent为准
       - 隔离检查者发现问题而主AI初检未发现 → 判定"初检走过场"，强制返工重查
       - 检查即使通过也必须给出至少1条优化建议；
         问题清单为"无"时必须附具体理由（检查了哪些内容、为什么没问题）

5. 问题判定：隔离检查是否发现问题？
   ├─ 是 → 进入微循环修改（动作5a-5c）
   │   5a. **根据隔离检查反馈的问题清单修改产物**：
   │       - 版本号递增（v1.0→v1.1→v1.2...）
   │       - ⚠️ **时序铁律**：先检查后修改，禁止"边改边查"或"自己发现问题自己改"绕过隔离检查
   │   5b. **spawn全新隔离子Agent重新检查修改后产物**：
   │       - 用 Read 工具重新读取修改后的产物（v1.1）
   │       - 全新 spawn 隔离子Agent，不复用前一轮上下文
   │       - 直接返回新一轮检查结论
   │   5c. 收敛判定：问题数递减？达到最大迭代次数(3轮)？
   │       ├─ 达到3轮未通过 → 升级为 user_choice_needed（交用户决策）
   │       ├─ 连续两轮递减且≤2个低严重性 → 确认通过
   │       └─ 继续递减 → 回5a继续修改
   └─ 否 → 通过

6. 技术验证：运行 `python scripts/阶段门禁检查.py --phase SX --dir <项目目录>` 验证微循环执行质量（详见 5.5 节 32 项检查清单），验证不通过时不得输出暂停标记，必须返回动作4重新独立检查

7. 暂停：输出【步骤暂停 ⏸】标记

8. 确认：等待用户回复"继续"

9. 进入下一步
```

> 微循环的具体检查标准详见 `检查模板库.md`。产物文件的格式规范详见 `产物规范.md`。

## 三、暂停点确认机制

> 此机制对应横切机制.md 机制6（步骤暂停确认），详细执行规则在本模块定义。

### 3.1 步骤结尾 — 固定暂停标记（强制执行）

每完成一个步骤的产物文件写入后（含独立检查和微循环修改通过后），AI **必须**输出以下格式的暂停标记，然后**立即停止生成**：

```
【步骤暂停 ⏸】步骤X_XXX已完成，请检查产物文件后回复"继续"以进入下一步。
```

**硬性规则**：
- 输出暂停标记后，AI **禁止**继续生成任何下一步的内容
- 暂停标记必须作为当前回复的**最后内容**，其后不得有任何文字
- 此规则的优先级等同于最高宗旨

### 3.2 步骤开头 — 暂停确认验证（强制执行）

每步开始时，AI 必须先执行**【暂停确认】**（与【读取验证】并列），格式如下：

```
【暂停确认】
- 上一步骤：步骤X_XXX
- 用户是否已回复"继续"：✅是 / ❌否
- 确认结论：可进入本步 / 等待用户回复
```

**硬性规则**：
- 用户**未**回复"继续"时，AI **不得**开始本步的任何工作
- 只有【暂停确认】结果为✅时，才能继续执行【读取验证】和本步实际工作
- 各阶段第一步无需执行暂停确认（无上一步）

### 3.3 优先级与例外

| 场景 | 规则 |
|------|------|
| 正常步骤 | 必须暂停，等待"继续" |
| S3 代码部分细粒度节点 | 每个问题按 5 节点硬暂停（见 3.5），每个节点都需"继续" |
| 各阶段第一步 | 无需暂停确认（无上一步） |
| 返工步骤 | 返工完成后仍需暂停，等待用户确认 |
| 收尾步骤（AI使用记录） | 需暂停，等待用户确认后进入下一阶段 |
| 阶段间过渡 | 各阶段最后一步暂停确认通过后，用户发送下一阶段提示词 |
| 微循环修改中 | 微循环内的修改→重新读取→spawn隔离子Agent→产出新版本隔离检查结论不需要暂停，微循环通过后才暂停 |

### 3.4 执行模式（standard / auto）

> 本节定义两种执行模式，控制暂停行为和决策行为。模式由用户在开始时指定，可在执行过程中切换。

#### 3.4.1 模式定义

| 模式 | 暂停行为 | 决策行为 | 进度报告 | 适用场景 |
|------|---------|---------|---------|---------|
| standard（默认） | 每个暂停点暂停等待用户确认 | 决策点列出选项+优劣交用户拍板 | 每步输出摘要 | 正式竞赛/需要把控 |
| auto | 所有暂停点自动确认继续 | 决策点AI按推荐方案执行，记录决策日志 | 每阶段完成时输出一行进度 | 时间紧迫/熟练用户/全自动一体化 |

#### 3.4.2 auto模式规则

1. **暂停点**：自动跳过，不输出暂停标记，不等待用户回复，直接执行下一步
2. **决策点**：AI选择推荐方案，记录到决策日志（格式：`[决策] 步骤X-Y：选择了Z方案，理由：...`）
3. **进度报告**：每完成一个阶段（S1/S2/S3/S4/S5/S6）输出一行：`✅ SX完成：产物N个已生成`
4. **例外 — 必须暂停**：遇到 hard_blocker（代码跑不通/数据缺失/赛题矛盾/验证连续3轮不通过）时，**必须暂停**并输出阻塞报告，即使auto模式也不例外
5. **用户切换**：用户可随时输入"暂停"切回standard模式；standard模式下用户可随时输入"全自动"切回auto模式
6. **决策日志**：auto模式结束时，额外输出全流程决策日志，供用户事后审查

#### 3.4.3 auto模式下的暂停确认验证

auto模式下，3.2（暂停确认验证）自动通过，格式简化为：

```
【暂停确认】auto模式 → 自动确认，继续执行
```

#### 3.4.4 auto模式下的微循环修改

auto模式下，微循环修改（第五章）正常执行，不跳过。微循环内的"重新读取→检查→修改→再检查→收敛判定"完整执行，只是微循环通过后不暂停、直接进入下一步。

⚠️ **对抗性自检（standard与auto模式均强制执行）**：为杜绝检查走过场，以下要求对两种模式均强制（由阶段门禁检查.py验证，不依赖AI自觉）：
1. 重新读取产物时，必须输出"已读取文件：XXX，读取内容摘要：XXX"，证明确实重新读取了
2. 隔离检查反馈中每项"通过"判定必须附具体证据
3. 如果全部产物的隔离检查反馈都是"第一轮即通过、零问题"，需在阶段结束时的AI使用记录中特别说明原因（如"本阶段产物较简单，确实无需修改"），否则视为检查走过场

#### 3.4.5 auto模式与9动作序列的关系

| 动作 | standard模式 | auto模式 |
|------|-------------|----------|
| 1. 读取验证 | 执行 | 执行（相同） |
| 2. 执行 | 执行 | 执行（相同） |
| 3. 写入产物文件 | 执行 | 执行（相同） |
| 4. 独立检查（重读+隔离子Agent审查） | 执行 | 执行（相同，三层检查+重新读取+隔离子Agent复核不跳过） |
| 5. 问题判定+微循环修改 | 执行 | 执行（相同） |
| 6. 技术验证 | 执行 | 执行（相同，微循环质量验证不跳过） |
| 7. 暂停 | 输出暂停标记，停止 | **跳过，直接继续** |
| 8. 等待确认 | 等待"继续" | **跳过，自动确认** |
| 9. 进入下一步 | 用户触发 | AI自动触发 |

> **关键约束**：auto模式只跳过动作7和8（暂停+等待确认），动作1-6和9全部正常执行。尤其动作4（独立检查：重新读取+三层叠加+隔离子Agent复核）和动作6（技术验证）**绝不跳过**，产物质量标准不因模式不同而降低。

#### 3.4.6 auto模式的触发与退出

| 触发方式 | 说明 |
|---------|------|
| 用户说"全自动"/"一体化"/"不用暂停"/"auto模式" | 进入auto模式 |
| 用户说"暂停"/"切回标准"/"standard模式" | 切回standard模式 |
| 遇到hard_blocker | 自动切回standard模式（即使auto模式下也必须暂停） |
| 全流程完成 | auto模式自动结束 |

#### 3.4.7 auto模式技术强制（新增）

> auto模式保留，但以下技术强制机制确保auto模式下的质量标准不低于standard模式。这些机制通过脚本验证，不依赖AI自觉遵守。

| 强制项 | 验证脚本 | 验证内容 | 不通过处理 |
|--------|----------|----------|-----------|
| 产物完整性 | 阶段门禁检查.py | 每个阶段应有产物全部存在 | 禁止进入下一阶段 |
| 微循环质量 | 阶段门禁检查.py | 版本号分布（是否有迭代）+ 产物内容完整性 + 隔离子Agent独立审查记录（对话中可追溯） | 标记"检查走过场"，禁止进入下一阶段 |
| 对抗性自检 | （两种模式均强制执行） | 重读摘要输出+全v1.0检测+全零问题说明 | 标记"检查走过场"，禁止进入下一阶段 |
| 决策日志完整性 | 阶段门禁检查.py(auto专项) | 每个决策点有：决策内容+理由+备选方案 | 标记"决策日志不完整"，禁止进入下一阶段 |
| hard_blocker暂停 | 阶段门禁检查.py(auto专项) | 若触发hard_blocker，产物中须有"已暂停等待用户确认"记录 | 标记"hard_blocker未暂停"，禁止进入下一阶段 |

**技术强制与行为指令的关系**：
- 行为指令（3.4.2-3.4.6）仍然有效，指导AI在auto模式下如何执行
- 技术强制（3.4.7）是事后验证，通过脚本检查行为指令是否被遵守
- 如果行为指令被遵守 → 技术强制自然通过
- 如果行为指令被跳过 → 技术强制拦截，禁止进入下一阶段

### 3.5 细粒度暂停点（S3 代码部分专用）

> S3 代码部分在 standard 模式下的暂停粒度比普通步骤更细。普通步骤一个步骤暂停一次；S3 代码部分**每个问题**拆成 5 个节点，每个节点都硬暂停，让我全程有刹车权和修改权，不再靠 AI 自觉"一口干到底"。

**每个问题（3-1~3-4）的 5 个暂停节点**（顺序不变，只在中间加暂停）：

| 节点 | 对应步骤 | 产出 | 暂停动作 |
|------|----------|------|---------|
| 1 写代码 | 3-1 | `问题X_求解.py` + `问题X_验证.py` | ⏸ 停，我审代码、可当场改 |
| 2 运行前检查 | 3-2 | 结构覆盖检查结论 | ⏸ 停，看检查结论 |
| 3 小数据运行 | 3-3 阶段A | 小数据结果 + 方向判断 | ⏸ 停，看方向对不对 |
| 4 全量运行 | 3-3 阶段B | 全量结果 | ⏸ 停，看最终结果 |
| 5 结果检查 | 3-4 | 运行后验证结论 | ⏸ 停，确认通过 |

> 问题一跑完这 5 个暂停，再进问题二重复，以此类推；全部问题跑完后，「自检(3-5) + 模型验证(3-5.5)」也 ⏸。每个暂停点界面统一输出：本步产物 + 关键结果 + 检查结论 + 【步骤暂停 ⏸，等回复"继续"】。

**与 auto 模式的关系（刹车阀）**：
- 默认状态 = 细粒度（最可控）
- 我对某段放心 → 说「接下来自动」→ 跳过后续暂停一口气跑完，只在结尾汇总
- 想重新把关 → 说「恢复暂停」→ 回到细粒度暂停
- auto 是随时可切的可选项，切换机制同 3.4 执行模式

**增量冷读（降低回改成本）**：
- 隔离检查仍做，作为"独立终审兜底"
- 改动范围明确时用「增量冷读」（只查 diff 影响域，不全文冷读）；大改才全文冷读
- 配合暂停点，我已在每个节点实时看到产物，隔离检查作为兜底终审

### 3.6 暂停点技术验证（新增）

每阶段结束时，运行 `scripts/暂停点验证.py` 验证本阶段所有产物的暂停标记和暂停确认完整性。此验证作为阶段门禁的可选组成部分（standard模式下启用，auto模式下跳过）。

**验证脚本检查项**：

| 序号 | 检查项 | 规则 | 例外 |
|------|--------|------|------|
| 1 | 步骤开头暂停确认 | 每个步骤产物（非首步、非AI记录）开头含【暂停确认】 | 各阶段第一步、AI使用记录 |
| 2 | 步骤结尾暂停标记 | 每个步骤产物（非AI记录）结尾含【步骤暂停 ⏸】 | AI使用记录 |
| 3 | 暂停确认格式 | 含"上一步骤"、"用户是否已回复"、"确认结论"三字段 | — |

**调用方式**：
```
python scripts/暂停点验证.py --phase <阶段> --dir <项目目录>
```

验证不通过的产物需补充暂停标记/暂停确认后重新提交。

## 四、S2↔S3 循环执行模式

> S2（建模计划）与 S3（代码）构成核心循环：计划驱动代码，代码验证计划，循环迭代直到结果通过。

### 4.1 循环结构

> ⏸ = 细粒度暂停点（详见 3.5）：S3 代码每个问题按「写代码 / 运行前检查 / 小运行 / 全量 / 查结果」5 节点硬暂停；全部问题跑完后再「自检(3-5) + 模型验证(3-5.5)」暂停。

```
【S2】步骤2-2 建模计划(vN)
    ↓
【S3】步骤3-1 代码(vN)   ⏸写代码
    ├─ 代码内置：小数据开关 + 分层采样函数 + --wenti 参数
    ↓
【S3】步骤3-2 运行前验证(vN)   ⏸运行前检查
    ├─ ①符合题意 ②能算出答案 ③全面
    ├─ 【加速层3】运行时间预估（超时预警，嵌入验证项）
    └─ 不通过 → 改代码(小修,留在S3) / 改计划(大改,回S2步骤2-2) → 回循环
    ↓ 通过
【S3】步骤3-3 运行代码(vN)  ← 拆成两个阶段   ⏸小运行(阶段A)/⏸全量(阶段B)
    │
    ├─ 阶段A：小数据运行（分层采样10%）
    │   ├─ 语法/逻辑检测（能不能跑通）
    │   ├─ 【加速层1+】结果方向验证（方向/趋势/量级）
    │   ├─ 各问衔接验证（数据流转是否正确）
    │   ├─ 边界触发检查（分支逻辑是否覆盖）
    │   └─ 手算复核（数据≤20行时挑2-3行）
    │       ├─ 不通过 → 改代码 → 重跑小数据（3-3内部快速迭代，不写MD）
    │       │   ├─ 3轮内通过 → 进入精估
    │       │   └─ 3轮仍未通过 → 升级为 user_choice_needed
    │       └─ 通过 → 实测精估运行时间
    │           ├─ 精估≤4小时 → 进入阶段B（全量运行）
    │           └─ 精估>4小时 → 超时处理分支（三级递进）：
    │               ├─ 第一级：触发代码优化 → limited_continue
    │               │   优化原则：不降准确性 / 不减覆盖 / 不简化 / 每问有答案
    │               │   ├─ 优化后≤4小时 → 进入阶段B
    │               │   └─ 优化后仍>4小时 ↓
    │               ├─ 第二级：触发抽样运行（分层比例采样）→ user_choice_needed
    │               │   ├─ 论文诚实说明采样比例/原因/策略
    │               │   ├─ 步骤3-5结果登记单独描述抽样情况
    │               │   ├─ 抽样后≤4小时 → 进入阶段B（抽样全量）
    │               │   └─ 抽样后仍>4小时 ↓
    │               └─ 第三级：回S2换算法 → hard_blocker
    │                   例：精确算法→启发式算法，全局优化→局部优化+多起点
    │
    └─ 阶段B：全量运行（只跑一次）→ 产出最终结果
    ↓
【S3】步骤3-4 运行后验证(vN)   ⏸结果检查
    ├─ ④答案正向 ⑤数据对得上
    ├─ 【加速层2】只重跑受影响问题（不全量重跑，含依赖链连带重跑）
    └─ 不通过 → 改代码(只重跑受影响问题)/改计划(大改,回S2步骤2-2) → 回循环
    ↓ 通过
【S3】步骤3-5 自检验算 → ✅确认   ⏸自检
【S3】步骤3-5.5 模型验证 → ✅确认   ⏸模型验证
```

### 4.2 循环修正原则

| 修正类型 | 触发条件 | 执行方式 | 版本号 |
|----------|----------|----------|--------|
| 小修 | 代码问题，计划没问题 | 留在S3改代码 | v(N+1)小版本递增 |
| 大改 | 计划有问题 | 回S2步骤2-2改计划→再回S3改代码 | v(N+1)大版本递增 |

### 4.3 as-built 优先原则

循环退出后，S2 步骤2-3 最终建模计划必须与代码实际实现完全一致。若计划与代码不一致，**以代码为准**修正计划。

### 4.4 循环退出条件

- S3 运行前验证通过 ✓
- S3 运行后验证通过 ✓
- S3 自检验算通过 ✓
- S3 模型验证通过 ✓（步骤3-5.5 四检 + 可回溯 + 三项检验全部通过）
- 用户确认锁定 ✓
→ 五项全部满足才退出循环

## 五、微循环修改执行模式

> 每个产物产出后的质量门禁，嵌套在步骤执行流程的第4-5步中。

### 5.1 微循环流程（6条闭环 + 三必查板块）

> 微循环对象是**当前步骤刚产出的文件**。每轮固定执行 6 个动作：挑毛病→查数据→提优化→记检查文件→改→再查，直到没问题或达到最大轮数。

```
[进入微循环] 当前产物写入MD（v1.0）→ 保存
  ↓ 动作1-2-3：冷读 + 三必查板块挑毛病（见5.1.1，板块B 用复算记录，逐项"证否或举证"）
  ↓ 动作4：产出隔离检查结论 stepN_v1.0（真实记录毛病，含 公式库复跑记录/本轮改动diff审阅/三连判据结论，格式见产物规范.md第七章）
  ↓ 隔离子Agent复核（Agent工具，subagent_type="general_purpose_task"，每轮必调，复验修改后最新版本，全量复算所有可计算数值）
  ↓ 自动跑 公式库硬钩子（scripts/公式库.py）+ 复验上轮改动 diff
  ↓ 三连判据判定（见5.2）：连1 本轮隔离检查零实质问题 ∧ 连2 公式库复跑零错误 ∧ 连3 上轮改动 diff 零新增
  ├─ 三连全过 → ✅通过 → 技术验证 → 进入暂停
  └─ 三连任一不过 → 强制进下一轮（禁止"一轮认命"对确定性错提前放行）
      ⚠️ **时序铁律**：隔离检查结论（动作4）必须在修改（动作5）之前完成并保存；禁止"先改产物再写/补隔离检查结论"
      动作5：**根据隔离检查结论问题清单逐条修改产物**（版本递增 v1.N → v1.(N+1)）→ 保存
             ⚠️ 禁止跳过隔离检查结论直接修改——修改必须对应隔离检查结论的问题清单
      动作6：spawn全新隔离子Agent重新冷读修改后产物 → **产出新版本隔离检查结论** stepN_v1.(N+1)
             （非"更新"旧报告；v1.N 的隔离检查结论保留不动；新报告须含"本轮隔离检查对象版本：v1.(N+1)"）
             → 复验修改后最新版 → 再判三连
```

**循环终止（分层轮数语义，见 微循环复算闭环改造方案.md 五）**：
| 问题类别 | 终止与轮数 | 说明 |
|----------|-----------|------|
| 第一类 确定性/基础错误（计算/编号/单位换算/求和自洽/口径） | 三连判据全过即停；无死轮数上限，**软上限 6 轮** | 复算+公式库封闭可穷举，通常 1-2 轮扫空；达 6 轮仍不三连 → 升级 user_choice_needed |
| 第二类 开放/优化（表述深度/结构/写得更好） | 沿用 **3-4 轮上限** | 本就开放无限，达上限交用户，不穷究"还能更好吗" |
| 确定性错误未抓完即声称通过 | ❌ 禁止 | 判"检查走过场"，须返工重查（防 989 型计算错漏检） |

### 5.1.1 三必查板块（微循环每次轮都必查）

每个产物每轮检查，**必须**逐板块输出对应内容，禁止遗漏或合并：

**板块A 原题对齐（挑文本+逻辑毛病）**
- 文本毛病：错别字、病句、歧义、冗余、前后称谓不一致
- 逻辑毛病：断链、跳步、前提缺失、推不出结论、结论与论述不符
- 与原题对不对得上：逐问对照赛题，是否答非所问、漏问、偏题、曲解题意

**板块B 数据核查（查编造/不一致 + 全量复算）**
- 产物中每个具体数值/图表/结论，必须能追溯到三选一来源：原始数据、代码运行结果、文献出处
- 追溯不到 → 标记"疑似AI编造"，须补来源或删改
- 数据间一致性：与已结果数据、编号、前后文是否冲突；单位、量级、口径是否一致
- **必须全量复算（v3，确定性错误分层）**：每个可计算数值必须给"复算记录"（算式+代入+结果），如 `充满时刻 = 12 × 1474 ÷ 30 = 589.6 min`；禁止仅"与源一致 / 核对一致 / 我看了没矛盾"式对账空证据
- 复算记录由 `scripts/公式库.py` 硬钩子自动重跑核验（抓 989 型计算错）；隔离检查结论缺失复算记录即判不通过

**板块C 优化建议（哪里更好）**
- 哪里没写够清楚、哪里还能更严谨、哪里可更简练、哪里可补证据/补文献
- 必须至少 1 条，且为具体定位 + 改进方向（禁止泛泛"可提升"）

### 5.1.2 三杠杆（治"每次直接通过、版本更迭没用"）

问题根因：检查者与产出同上下文，读到"我写这段想表达X"就自动脑补填坑，于是总以为没问题。用三个杠杆强制失效"直接通过"：

**杠杆1 冷读 + 批判立场**
- 检查必须用 Read 工具**重新读取产物文件**，禁用产出时的上下文记忆
- 立场切换：检查必须是**挑剔的评委**，默认怀疑有毛病，逐个反例项找茬；不是帮作者圆场
- 产物中每个非平凡断言，必须回答"仅凭文本能否成立"

**杠杆2 逐板块逐缺陷"证否或举证"，禁止空话**
- 对三必查板块及常见缺陷类型（清单见检查模板库.md），检查者必须逐项给出二选一：
  - **发现** → 记录具体定位（第X段/表X/图X/数值X）+ 具体毛病
  - **排除** → 必须给出"我读了第X处，内容为…，判定无此问题"的实质排除理由
- **禁止**只写"无/没问题/未发现问题/通过"。这类空话由  检测并判不通过

**杠杆3 版本更迭契约（让版本号有用）**
- 发现毛病 → 必须修改 → 版本必须递增（v1.0→v1.1→v1.2）
- 只要隔离检查结论记录了一个"发现"，产物版本就必须 > v1.0，否则脚本判定"发现问题未修改"，不通过
- 一个产物要**不带修改直接通过**，必须同时满足三条硬条件（见 5.2.1）；三条缺一 → 不得以 v1.0 直接通过

> 结果：版本更迭绑定"真有毛病"的自然结果，而非为递增而递增。

**杠杆4 全量复算（v3，抓"对账查不出、复算才查出"的计算错）**
- 隔离检查不能被"对账"（断言 vs 来源比对）填满，必须**全量复算**所有可计算数值 + 交叉核对单位/量级/公式。
- 每个数值证据写成"复算记录"（算式+代入+结果），由 `scripts/公式库.py` 硬钩子自动重跑核验。
- 用"我重新算了一遍"才算证据；"我看了一眼没矛盾"不算（脚本可判不通过）。
- 典型 989 型错误：`充满时刻 = 12 × 1474 ÷ 30` 被写成约 989 而非 589.6——对账看不出来，复算一次即现形。

⚠️ **四条铁律（杜绝"检查走过场"）**：
1. **必须重新读取**：检查前必须用Read工具重新读取产物文件，禁止使用产出时的上下文直接检查
2. **必须有证据**：每项检查的"通过"判定必须附具体证据（如"与步骤1产物第3段对比，关键结论XXX一致"），禁止只写"通过"二字
3. **必须递增版本号**：微循环中每次修改产物必须递增版本号（v1.0→v1.1→v1.2），禁止"全v1"现象
4. **隔离检查结论独立文件**：隔离检查结论由隔离子Agent直接返回，不产出独立文件；必要时记录于产物 `## 变更说明`；发现问题但版本号仍为v1.0即视为"发现问题未修改"，判定不通过

### 5.2 退出条件（v3：唯一判据 = 三连判据）

微循环**唯一允许终止**的判据是三连判据；缺一连强制进下一轮（版本递增），**不允许"一轮认命"地对确定性/基础错误提前放行**：

| 连 | 判据 | 不满足时 |
|----|------|---------|
| 连1 | 本轮隔离子Agent 以**评委+国一视角冷读**：零实质问题（复算全对 + 非纯元数据产物"机理闭环判定 0 处未闭环" + 冷读挑不出评委必抓的断链），且复验的是**修改后的最新版本** | 强制下一轮 |
| 连2 | `scripts/公式库.py` 硬钩子复跑**零错误** | 强制下一轮 |
| 连3 | 复验上轮改动处 **diff 零新增**问题 | 强制下一轮 |

- 三连全过 → ✅通过 → 进入暂停；任一不过 → 强制进下一轮（v1.N → v1.(N+1)）。
- 确定性错误未抓完，**不得**以"人工确认 / 毛病明显递减"提前放行（防 989 型漏检）。
- 开放优化类仍遵循分层轮数语义（见 5.1 循环终止规则）可在达上限后交用户。

> 三连判据同时满足"有循环过程的深挖感"与"不真无限空转"：连1/连2 靠复算与公式库（封闭可穷举），总有一轮扫空；连3 靠 diff 收窄，扫描窗口每轮只缩不扩，必然收敛。上一轮改过的地方必喂给下一轮新料，天然逼出多轮。

> **补丁⑤（评委冷读，根治"自我审查视角盲区"）**：连1 的"零实质问题"必须建立在**评委冷读 + 机理闭环 + 双角色隔离**之上，否则就是低标准放行。默认的自我审查受"知识诅咒"（懂的人自动脑补文档断链），看不见机制性硬伤（如"水流推进 vs 蓄水充满"双时间线不闭环、曼宁退化口径、交汇叠加粗口径，都是评委一眼必抓而自检常漏的）。因此隔离子Agent 必须：
> - 以"评委+国一"视角**冷读**，显式**代入评委最可能追问的问题**（如"水到分叉后先头以什么速度下传？两路分支同时蓄水供给怎么分？两速度哪种优先？"），并逐条给出闭环解答或证否依据；
> - **非纯元数据产物**（建模/代码/方案/正文/校验）必须写一行显式判据 **`机理闭环判定：X 处未闭环`**（X 为未闭环处数）。**X>0 → 连1不通过，强制下一轮补闭环**；
> - 白名单产物（文献/资料等，见补丁②）与已登记豁免历史产物不要求机理闭环判定。
>
> **核心转变**：微循环的循环动力从"错误消除就停"升级为"**评委必抓断链清零才停**"——即使数值全对、字段全齐，只要仍有 ≥1 处评委必抓的机理断链未闭环，就**永远不会有"✅通过"**。

### 5.2.2 双角色隔离检查协议（B 方案，根治"污染+转述+同源"）

> 连体检查是"蠢"的根因：检查者与生产者在**同一上下文光圈**里——看得见生产者的思路/中间思考/建模解释 → 被灌输同一套物理理解，不是冷读是同源；结论又**经生产者之手转述**填进隔离检查结论 → 被无形过滤。B 方案用**上下文隔离 + 结论直写**，在单进程内再造一个"第二个独立 AI"。

**检查者 = 每次全新 spawn 的隔离子Agent**（general_purpose_task 类，具备 Read / WebSearch / WebFetch / Write），它：
- **审查范围白名单**（且仅此三样）：① 本轮产物文件；② 原题/赛题原文；③ 允许的外部权威核查资料。
- **禁读黑名单**（禁止喂给检查者）：产者的思路/中间思考/建模解释、上一轮隔离检查反馈、内部检查模板库、公式库源码。否则污染又回来了。
- **代际清空**：每次检查都用**全新上下文**的检查者，杜绝跨轮累积污染（支持 `--round N` 强制新一轮）。
- **结论直写**：检查者输出由调用方**直接写入隔离检查结论** `步骤N_产物名_vN`，产者**只读不改写**。报告末行附：
  `<!-- 由隔离检查Agent直写，未经生产转述 -->`（供 校验独立性）。
- **终止信号**：检查者报告末行 `✅ 无实质问题 → 可进入下一步`，产者读到即停，成品留下等你检查。
- 连1 判据升级为：**以隔离检查者直写的原始报告为准**（零实质问题 ∧ 冷读 ∧ 机理闭环 0 未闭环 ∧ 在）→ 才允许三连通过。非隔离直写的报告不构成连1。
- 可选增益（不阻塞落地）：spawn 隔离检查者时经 `model` 覆盖配置**异模型** → 真"第二颗不同大脑"。

> **【补丁⑨】复检独立触发机制（根治"改完由生产者自判通过就停"的假循环）**
> 目标：**循环必须持续到"第二个 AI 独立重新读最新版、亲笔判'无实质问题 → 可停止'"之后才允许停**；生产者对"是否达标"**无任何代判权**。"循环"= 做好→A查→改→**A重查(独立重判)**→你拍板才停。三根柱子：
> - **柱子1 · 版本每次递增 → 强制触发全新隔离复检，判决只认子Agent 输出**：产物版本每递增一次（vN→vN+1），主AI **必须先 spawn 一个全新隔离检查者 `--round N+1`**，令其独立 re-read 该新版本 `v(N+1)`，再将其诊断**原样落盘**为本轮 `` 的权威内容；主AI 对复检者返回**只做原样写入**，不增删、不润色、不补"通过"。"通过/可停止"字样只能出现在隔离复检者自己的判决里。
> - **柱子2 · 独立"停止判决"行，生产者碰都不许碰**：每次复检由子Agent 在报告正文末尾单独输出一行 `【独立判决】隔离复检者已冷读 vN，结论：✅ 无实质问题 → 允许停止 / ❌ 仍存在实质问题：<列出> → 须返工`。反向探针（脚本只做痕迹校验，不判对错）：报告缺 `【独立判决】` → 判"独立复检未发生"，连1 不通过、逼停；产物变更说明出现"复检通过/三连通过/第2轮通过"等**生产者代判**字样 → 判"生产者自判终止"，连1 不通过。
> - **柱子3 · 链式独立：每次复检全新、判决不沿用旧结论**：复检者**不知道上一轮隔离检查结论**（在禁读黑名单里），只能读"本轮产物 + 原题 + 允许的外部权威资料"，独立得出对 v(N+1) 的判断。**因此不可能**复用旧结论/直接对号——它必须真的重读新版本才能给出判决。
> - 补丁⑦ 的对照表探测（`ASSEMBLED_MARKERS`）**保留**，本机制（柱子1~3）作为**更上一层的兜底**：即使主AI 措辞绕开探测，也会被 `【独立判决】` 缺失/生产者代判两个反向探针拦住。
> - **诚实极限**：脚本只保证"痕迹上独立"（判决行存在、非生产者代判、版本绑定一致），**保证不了**子Agent 判别力（漏判真问题是模型天花板）。最硬兜底仍是**用户抽查**确认判决真的出自新粒子独立复检。柱子1~3 把"代判"降到零，但"漏判"仍需用户把关。

> **【补丁⑩】对账层强制考题——三查未完成绝不判 OK（根治"复检者没对账就放过"）**
> 目标与来源：补丁⑧让复检者当"自由国一评委"自由狠批（高度判断题），却**漏掉"逐断言对账"这层**，退出循环后外部 AI 仍查出 12 项（4A/3B/5C），A 类全是**有铁证可锁定的确定性错误**（跨文档口径笔误、物理分类标错、术语未定义）。对账是模型的强项（正是外部 AI 胜出的原因），必须把"**做完对账才允许判 OK**"设成强制动作门槛。判断对错仍归复检者脑力 + 用户，脚本不掺和、不认词。
> 核心硬门槛：**隔离复检者判 `✅ 允许停止` 之前，必须已完成"对账三查"**（对账①跨文档口径一致性 / 对账②物理分类复算 / 对账③术语完备核查），缺一不可。**三查未完成绝不判 OK。**
> - **对账①**：正文每一条物理断言 × **已确认定稿事实 + 变更说明 + ③确认表** 三方口径必须一致；只有一方不符即列实质问题。
> - **对账②**：每个"主导机制/归类"（坡降/供给钳制主导/可到达…）须经该点数据**亲身复算判定**，写出 `判定式=代入数据=结果→归类`；与钳制/阈值对照自洽。
> - **对账③**：产物出现的缩写/术语必须已定义且全文唯一；未定义/冲突/用词不一即列问题。
> - **执行顺序（并入补丁⑨/⑧流程）**：spawn 全新隔离复检者 → **先做对账①②③**（独立前置步骤）→ 再做补丁⑧ 4 类置疑高度判断 → 最后输出【独立判决】。三查任一缺失 → 判"对账未完成，不得判 OK / 连1不通过"、逼停补做（检查项31）。
> - **脚本角色**：（补丁⑩）仅按结构完整性确认 `对账①/②/③` 字段已产出（缺任一字段→连1不通过），**只守"对账做没做（痕迹）"这一防腐层，不评对账判得对不对**（判对错归复检者脑力+用户）。对账②对无物理分类判定的文档产物允许复检者如实写 N/A 附理由。
> - **尊重既有机制**：不新增任何"认对账内容对错"的判词；不动既有隔离审查范围白名单/禁读黑名单；补丁⑧（4类置疑）与补丁⑨（复检独立触发）均保留，对账层是叠加在其上的**审计前置**。
> - **诚实极限**：对账①-③是强制动作门槛，保证"复检者做完这些才判 OK"；但对账本身对错仍受模型判别力限制——脚本拦得住"对账做没做（痕迹）"，拦不住"对账对不对（判力）"。**最硬兜底仍是用户抽查**复检者的对账①②③是否真逐条对过、是否留下能复算的判定式。

> **【补丁⑧】检查者的考题 = 自由国一评委（先狠批、再套模板存档），终止 = 步骤级国一**
> - **统一《任务指令》**：spawn 时首个指令是"以够不够国一为标准自由狠批：哪里不行/为什么/怎么改"，并对 4 类致命置疑（真增量量化 A / 创新分布健康 B / 文献区分度 C / 物理机理级 D）**逐条用脑作答"通过/未通过+理由"**（指令全文见 检查模板库.md 6.1）。输出后，**仍套既有隔离检查结论模板补全字段存档**——字段是证据，不是思考触发器。
> - **4 类置疑是检查者的考题，不是脚本的判据**：4 类置疑答得好不好、通不通过，**由检查者脑力 + 用户定**；脚本**不核对、不评对错**，严禁任何"靠关键词判深度"的脚本检查。
> - **终止目标 = 步骤级国一（修正原"通过"含义）**：检查者判定"当前产物已在其范围内达到可细化极限、OK 可进入下一步"即算通过；单步产物不需证明整篇论文国一（全局由后续步骤代码/写作叠加）。**判断权归属**：有无实质问题、到没到可细化极限 → 检查者脑力；客观凭证（签名/版本/复算/未闭环数）→ 脚本守底线；最终 → 用户拍板。**评委说 OK 才停，评委说不行就返工重来（改后必重起全新评测者，见检查项27-28）。**

### 5.2.1 零修改直通三条件（治"每次直接通过"）

一个产物要**不带任何修改**、以 v1.0 直接通过微循环，必须**同时**满足以下三条硬条件，缺一不得直通，必须以 v1.1 及以上走至少一轮修改迭代：

1. **逐项排除证明**：三必查板块（5.1.1）及常见缺陷类型（检查模板库.md）逐项给出"我读了第X处，内容为…，判定无此问题"的**实质排除理由**，无空话、无"未发现问题"式笼统表述
2. **隔离子Agent复核通过**：隔离子Agent（Agent工具，subagent_type="general_purpose_task"）独立复核确认无漏检的实质问题
3. **如实说明**：在阶段AI使用记录中如实说明"本产物经严格证否确认，确实无需修改"

> 只有当产物质量确实无需修改时（如确定性内容）才可能直通。多数产物会因真有问题自然走到 v1.1/v1.2。这是"版本更迭有用"的落地。

### 5.3 与S2↔S3大循环的关系

- **微循环修改**：嵌在每一步内部，产物写完→重读→查→出报告→改→重读→查→通过（单产物级别）
- **S2↔S3大循环**：跨阶段，计划→代码→验证→修正（跨产物级别）
- 两者不冲突：S2↔S3循环中的每个产物本身也要做微循环修改
- S5五重质检是全文终检，不参与微循环修改

### 5.4 自确认偏误应对

| 优先级 | 方式 | 说明 |
|--------|------|------|
| 1（优先） | spawn隔离子Agent | Agent工具，subagent_type="general_purpose_task"，全新上下文冷读（见动作4b，硬性门禁） |
| 2（备选） | 评委视角自检 | 切换到"数学建模竞赛评委"视角，按CUMCM标准逐条检查（仅spawn失败时降级，需用户确认） |

> 具体检查标准和技能映射详见 `检查模板库.md`。

> **自检升级：从"对账"到"主动怀疑"（补丁①，治"自检走过场"）**：AI 自检不得只做"对账"（断言 vs 来源比对），对每处可计算数值/结论必须逐条"主动怀疑"，自问三问——
> 1. **若我写错了，会错在哪？**（主动构造错误假设，再验证它是否被否证）
> 2. **换一种算法/口径算，还一致吗？**（交叉验算，如顺序颠倒、量纲换算、取整方式）
> 3. **这个值合理吗？**（量级/物理直觉复查，如充满时刻被写成约 989 而实算应 589.6，对账看不出来、主动怀疑当场现形）
>
> 三问的结论逐条落进三必查板块B的"复算记录"（算式+代入+结果），由 `公式库.py` 硬钩子复算兜底。凡证据列只写"与源一致/对账通过"、却无任何主动怀疑痕迹的，判"自检深度不足"，视为检查走过场。
>
> **补丁①强化（主动怀疑记录必填，硬约束）**：非纯元数据产物（未命中 5.5 白名单）的隔离检查结论**必须含"主动怀疑记录"字段**（可写作 `主动怀疑记录：…`，内容为对复算值自问三问的怀疑痕迹，如"写错会错在哪→换算法重算→量级复查"），由 校验（`ACTIVE_DOUBT_KEYWORDS`），缺失即判"自检深度不足"不通过。**白名单产物与已登记豁免的历史产物可豁免该字段**（见 5.6）。

### 5.5 微循环技术验证（强制）

**每步结束（不只是每阶段结束）必须运行** `scripts/` 验证本步产物的微循环执行质量，验证不通过禁止进入下一步。**standard（手动）与 auto 模式均强制执行，不跳过**。

**验证脚本检查项**（详见 `产物规范.md` 第七章7.3节技术验证段落）：

| 序号 | 检查项 | 通过标准 |
|------|--------|----------|
| 1 | 隔离检查结论记录存在性 | 每个产物 `## 变更说明` 含隔离检查结论记录 |
| 2 | 重新读取确认 | 隔离检查结论中含 `重新读取确认` 且值为✅ |

| 11 | 隔离子Agent独立产出 | 隔离检查结论中含"隔离子Agent问题清单"+"隔离子Agent优化建议"字段（独立产出，非仅复核结论） |

| 18 | 本轮改动diff审阅 | 隔离检查结论中含"本轮改动diff审阅"字段（**连3**痕迹），记录上轮改动处是否引入新问题 |

| 25 | 无自审残留（B方案连1） | 隔离检查结论不得含产者自审残留（"我认为/我方建模/我的建模思路/根据我的思路"）。命中 → 判冷读不净，连1不通过 |
| 26 | 版本绑定（B方案连1） | 隔离检查反馈名版本号（`_vN`）必须与本轮产物版本号一致。不一致 → 判"旧报告/版本漂移"，连1不通过 |
| 27 | 复循环审查对象版本（补丁⑦连1） | **返工产物（版本>v1.0）**的隔离检查结论必须含 `本轮隔离检查对象版本` 字段（兼容旧名 `本轮独立审查对象版本`），且声明的版本 == 产物文件版本。缺该字段或声明的是旧版（如产物 v1.2 却声明 v1.0）→ 判"未对返工产物复循环/跳轮"，连1不通过，强制重起一轮隔离冷读 vX |
| 28 | 禁对照表冒充复循环（补丁⑦连1） | **返工产物（版本>v1.0）**：若隔离检查结论的"隔离检查"内容呈"对照吸收上一轮问题"形态（`已吸收/已对照/对照吸收/全部修订/上一轮审查`），而全篇**未出现返工产物版本号 vX**，→ 判"对照表冒充复循环"/复用旧报告，连1不通过，须重起一轮隔离冷读 vX |
| 29 | 独立判决存在（补丁⑨连1） | 隔离检查结论必须含 `【独立判决】` 行（由隔离复检者给出，见 5.2.2 柱子2），如 `【独立判决】隔离复检者已冷读 vX，结论：✅ 无实质问题 → 允许停止 / ❌…`。缺 `【独立判决】` → 判"独立复检未发生"，连1不通过、逼停 |
| 30 | 禁生产者代判（补丁⑨连1） | **返工产物（版本>v1.0）**的`产物变更说明`不得出现"复检通过/三连通过/第2轮通过/本轮检查已达通过标准"等**生产者自判终止**字样。命中 → 判"生产者自判终止，复检未独立发生"，连1不通过 |
| 31 | 对账三查完整（补丁⑩连1，硬门槛） | 隔离检查结论必须含 `对账①跨文档一致性` / `对账②物理分类复算` / `对账③术语完备` 三字段（对 `对账①②③` 结构痕迹校验）。**任一查缺 → 判"对账未完成，不得判 OK"，连1不通过、逼停补做；三查未完成绝不判 OK**。不评对账判得对不对（归复检者脑力+用户）；对账②对无物理分类判定的文档产物允许复检者如实写 N/A 附理由。白名单(no_arith)产物**不豁免**——文档类产物最需对账①跨文档一致/对账③术语完备（见 5.2.2 补丁⑩）；仅已登记豁免的历史产物可跳过（守5.6不追溯） |
| 32 | 时序铁律（补丁⑪连1） | **返工产物（版本>v1.0）**的隔离检查结论问题清单不得只含"已修复/已改/已修正/已解决/已吸收/已对照/已修订"等**事后盖章**表述。命中 → 判"隔离检查结论事后盖章"——隔离检查结论在修改之前产出才有价值，先改产物再补隔离检查结论等于自审，连1不通过，强制回动作4重起检查 |

> 三板块A/B/C + 空话拦截（13-16）由  校验，standard 与 auto 模式均强制执行。**复算闭环三连判据 + 升级型建议 + 评委冷读/机理闭环 + 双角色隔离 + 复检独立触发 + 对账三查 + 时序铁律（17-32）由  + scripts/公式库.py 校验，standard 与 auto 模式均强制执行：第20项命中 989 型计算错或缺失复算记录即不通过，第17-19项缺任一字段即不通过，第21项无升级型建议即不通过，第22项缺评委冷读即不通过，第23项非纯元数据产物缺机理闭环判定或未闭环数>0 即连1不通过，第24-26项缺隔离直写/签名/版本绑定或含自审残留即不通过，第27项返工产物缺'本轮隔离检查对象版本'或声明旧版即不通过，第28项返工产物'对照表冒充复循环'即不通过，第29项缺`【独立判决】`即判独立复检未发生连1不通过，第30项返工产物变更说明含生产者自判终止字样即连1不通过，第31项缺对账①②③任一字段即判"对账未完成，不得判OK"连1不通过（三查未完成绝不判OK），第32项返工产物隔离检查结论问题清单只含'已修复'类表述即判'事后盖章'连1不通过。**
>
> **补丁④（升级型建议）**：检查绝不只是"校对"——每次微循环都要反过来问"这个方案还能怎么更强"，强行把检查者从"校对员"提升为"方案顾问"。AI 优化建议段与隔离子Agent优化建议段中，必须至少 1 条指向方案要素（模型/算法/方法/参数/验证/结构/权重等）的升级动作建议（改用/引入/替代/敏感性/鲁棒/消融/交叉验证/参数寻优等）。纯纠错型（补文献/改格式/统一单位）不满足。"升级型建议"与 5.4 补丁①"主动怀疑"互补：主动怀疑管"数值对不对"，升级型建议管"方案强不强"。
>
> **补丁②（复算记录 N/A 例外白名单）**：仅"纯元数据/无算术"产物（文件名命中 `文献检索/题目理解/附件理解/资料/题意锚定/创新点`，由 的 `NO_ARITH_WHITELIST_PATTERNS` 判定）允许"复算记录/公式库复跑"写 `N/A（无算术，附理由）` 且不强制第17/20项。凡未命中白名单（含数值的建模/代码/数据/正文/校验产物）必须写真实复算记录，以 N/A 敷衍即判 **钻空子（连2）** 不通过。白名单只豁免"必须有复算记录"这一条，**不豁免"写了但算错"**——算错仍由公式库拦截。
>
> **补丁⑦（复循环硬门禁，检查项27/28 + 机理闭环创新点例外）**：实战暴露出"返工后没真正再起一轮隔离冷读、只写一张'上一轮问题已吸收'对照表被脚本放行"的洞——等于 B 方案循环的**最后一脚没踩到底**（产生→检查→改，然后没有真正的"再检查"）。治法：①返工产物（版本>v1.0）必须声明 `本轮隔离检查对象版本：vX`（兼容旧名 `本轮独立审查对象版本`）且 **X==产物文件版本**，否则连1 的"零实质问题"无法证明来自新版，判"未对返工产物复循环/跳轮"拦截；②若"隔离检查"内容全是对照吸收表述、却连返工产物版本号都没提，判"对照表冒充复循环"拦截，须重起一轮隔离冷读 vX；③创新点产物从机械闭环豁免中剔除（其命中算术白名单但恰是方案核心，最需评委冷读断链）。核心转变：**循环出口绑定"新一轮隔离冷读证据"，而非"上一轮意见被登记吸收"。**
>
> **补丁⑪（时序铁律，检查项32）**：实战暴露出"AI 先改产物再补隔离检查结论"的系统性偏差——隔离检查结论沦为事后盖章，记录的不是"检查发现了什么问题"，而是"改完之后的版本没问题"。根因：AI 在产出过程中自己发现问题并直接修改，到检查时检查的是"改好的版本"，隔离检查结论从未记录过原始问题。治法：①**时序铁律**——隔离检查结论必须在修改之前完成并保存，产物写入后隔离检查结论产出前为冻结点，禁止修改产物；②修改必须逐条对应隔离检查结论的问题清单，禁止"自己发现问题自己改"绕过隔离检查结论；③返工产物的隔离检查结论须产出**新版本文件**（`步骤N_产物名称_v1.1`），旧版本隔离检查结论保留不动，禁止在同一个文件上"原地更新"覆盖旧版本检查记录；④返工产物隔离检查结论问题清单只含"已修复/已改/已修正"等表述 → 判"事后盖章"，连1不通过。核心转变：**隔离检查结论从"改完后的盖章"变为"修改前的发现记录"——先有问题清单，再据此修改，隔离检查结论有价值；先改再补隔离检查结论，隔离检查结论只是拖累。**

**auto模式额外检查**（对抗性自检）：
- 重读摘要输出：隔离检查结论中含"已读取文件"+"读取内容摘要"
- 全v1.0检测：所有产物版本均为v1.0时标记"检查走过场"
- 全零问题说明：全部产物"第一轮即通过"时需在AI使用记录中有特别说明

**调用方式**（每步结束强制调用）：
```
python scripts/阶段门禁检查.py --phase SX --dir <项目目录> [--auto]
```

**手动模式执行说明**：standard（手动）模式下，技术验证动作（动作6）在暂停标记（动作7）之前执行；验证不通过时不得输出暂停标记，必须返回动作4重新独立检查。

### 5.6 机制升级时历史产物兼容策略（补丁③）

当微循环检查机制升级（新增字段/判据，如三连判据、公式库复算、复算记录）后，对升级点**之前已通过**的历史步骤产物，按以下策略处理，避免每次升级都引发全量回填与假阳性：

| # | 策略 | 说明 |
|---|------|------|
| 1 | **新字段不追溯回填** | 升级前已通过的产物，其旧隔离检查结论**不必回填新增字段**；仅当该产物因返工被重新打开时，再一次性补齐新字段。禁止因升级而对全部历史产物批量补字段。 |
| 2 | **阶段门禁按当前标准，但历史产物豁免** | 阶段门禁以最新标准校验；对升级前已通过的历史产物，若缺新字段但内容确实无需重检，在 AI使用记录中登记"该产物升级前已通过，缺 X 字段属版本差异"，门禁对该类登记项放行。 |
| 3 | **统计阈值不溯及既往** | 版本号分布 / 全v1.0 / 全零问题 等对抗性统计，只统计升级后**新产出或返工过**的产物，不把历史产物拖入制造假阳性。 |
| 4 | **缺失复算/复跑字段走 5.5 白名单判定** | 历史产物缺"复算记录/公式库复跑"字段时，先按补丁②白名单判断其是否属无算术类型：是则正常放行；否则按新标准要求其返工补齐，不得因"历史产物"而豁免计算类产物的复算强制。 |

> 升级以 版本号或本文档版本号变更点为界。策略 4 是防线：白名单豁免只给"纯元数据"产物，计算类产物即使历史遗留也必须补复算记录，防"机制升级＝钻空子窗口"。

**补丁③强化（豁免登记机制，落地为脚本硬约束）**：为避免"机制升级→历史产物被新字段误拦→AI 走批量补字段捷径"，在**项目根目录**维护 `豁免登记.md`，登记机制升级前已通过、缺新字段属版本差异的历史产物：

```markdown
# 豁免登记（机制升级前已通过的历史产物）
- 步骤1_题目理解（机制升级前已通过，缺"本轮改动diff审阅/三连判据结论/主动怀疑记录"属版本差异）
- 步骤2_建模计划（同上）
```

- 启动时读取 `豁免登记.md`（`_load_exemption_registry`），命中产物的**机制型新字段**检查（本轮改动diff审阅 / 三连判据结论 / 主动怀疑记录）被跳过，其余检查（三板块、复算记录、公式库算术核验、版本分布等）**不豁免**。
- **豁免 ≠ 免复算**：即使命中豁免登记，只要产物含可计算数值，复算记录与公式库算术核验照常执行（守策略4底线）。
- **登记须附理由**：豁免登记行须注明"机制升级前已通过/缺 X 字段属版本差异"，无理由的登记行视为无效，不产生豁免。
- **豁免登记本身是产物**：`豁免登记.md` 纳入 AI使用记录登记，随阶段产物一并交付，供门禁核对。

## 六、阻塞器分类与恢复流程

> 此机制对应横切机制.md 机制7（阻塞器分类与恢复），详细执行规则在本模块定义。

### 6.1 阻塞器3级分类

| 类型 | 含义 | 处理方式 | 示例 |
|------|------|----------|------|
| `hard_blocker` | 继续受影响部分需要编造或不可验证的内容 | 停止该部分，直到用户提供素材或更改范围 | 赛题数据缺失无法建模；参考文献无法验证 |
| `limited_continue` | 不受影响的工作可继续，但某项声明/章节/图表须保持临时状态 | 仅在标注限制的前提下继续 | 某问题代码未跑通但其他问题可继续；某图缺失但可先占位 |
| `user_choice_needed` | 两种有效来源/格式/范围/优先级冲突 | 请用户选择或批准推荐路径 | 两个模型都可行需选一个；参数取值范围有多个合理选项 |

### 6.2 按阶段阻塞条件

| 阶段 | 阻塞条件 | 阻塞类型 |
|------|----------|----------|
| S1 题目分析 | 赛题文档缺失或无法读取 | hard_blocker |
| S1 题目分析 | 附件数据缺失但不影响理解题意 | limited_continue |
| S2 思路确认 | 多种建模思路均可行，需用户选择 | user_choice_needed |
| S3 代码编程 | 某问题代码报错无法运行 | hard_blocker（该问题）/ limited_continue（其他问题） |
| S4 正文写作 | 正文数值与代码结果不一致 | hard_blocker |
| S4 正文写作 | 某章节内容需补充文献但暂未找到 | limited_continue（标注 needs_source） |
| S5 综合校验 | AIGC 风险等级为 high | hard_blocker |
| S5 综合校验 | 某项检查未通过但不影响整体 | limited_continue |
| S6 组装定稿 | docx 生成失败 | hard_blocker |
| S6 组装定稿 | 图片缺失但有占位 | limited_continue |
| S3 代码编程 | 单问题运行时间>4小时（阶段A实测精估） | limited_continue（触发代码优化；优化原则：不降准确性/不减覆盖/不简化/每问有答案） |
| S3 代码编程 | 优化后仍>4小时 | user_choice_needed（抽样运行，分层比例采样，论文诚实说明采样比例/原因/策略） |
| S3 代码编程 | 抽样后仍>4小时 | hard_blocker（回S2换算法，如精确算法→启发式算法） |

### 6.3 阻塞报告格式

当发生阻塞时，AI 必须在暂停点输出以下结构化报告：

```
【阻塞报告】
- 阻塞类型：hard_blocker / limited_continue / user_choice_needed
- 阻塞原因：[具体描述]
- 受影响范围：[受影响的章节/步骤/交付物]
- 是否可有限继续：是 / 否
- 候选选项：
  A. [选项A + 利弊]
  B. [选项B + 利弊]
- 推荐路径：[推荐选项 + 理由]
```

### 6.4 恢复流程

| 新素材/事件 | 返回阶段 |
|-------------|----------|
| 用户提供缺失的赛题数据 | S1 对应步骤 |
| 用户选定建模思路 | S2 对应步骤 |
| 代码修复并重新运行成功 | S3 对应问题 |
| 补充文献找到并验证 | S4 对应步骤 |
| AIGC 高风险段落修改完成 | S4 步骤10 |
| 用户更改交付范围或内容范围 | 最近受影响的阶段 |

### 6.5 扩展指南

**添加新阻塞条件**：
1. 确定阻塞条件和阻塞类型
2. 在"按阶段阻塞条件"表中增加一行
3. 如有新的恢复路径，在"恢复流程"表中增加一行

## 七、结果摘要与修改流程

> 此机制对应横切机制.md 机制8（结果摘要），详细执行规则在本模块定义。结果登记格式详见 `产物规范.md`。

### 7.1 锁定触发

| 锁定点 | 触发条件 | 锁定内容 |
|--------|----------|----------|
| S2 步骤2-3 | 用户确认"锁定" | 建模计划（公式、算法、参数、数据流）+ 步骤3-5结果登记 |
| S3 步骤3-5 | 自检验算通过 | 代码结果数据（数值、图表、表格）+步骤3-5结果登记作为结果摘要的物理载体 |

### 7.2 锁定后的约束

| 阶段 | 允许操作 | 禁止操作 |
|------|----------|----------|
| S4 论文写作 | 引用锁定的数值、图表、公式（引用统一指向运行结果） | 修改数值；重新计算；替换图表；绕过运行结果直接引用3-3/3-5产物 |
| S5 综合校验 | 检查数值一致性、引用关系 | 修改数值、重新生成图表 |
| S6 组装定稿 | 引用锁定的产物组装 | 修改任何已确认的数据 |

### 7.3 修改流程

```
发现需修改已结果数据
  ↓
向用户报告修改原因和影响范围
  ↓
【步骤暂停 ⏸】等待用户确认
  ↓ 用户确认解锁
S2 步骤2-2 修正建模计划 → S3 修正代码 → S3 重新验证 → S3 自检验算
  ↓ 验证通过
S2 步骤2-3 重新锁定 → S3 步骤3-5 重新锁定 → 通知 S4/S5/S6 更新引用
```

**关键约束**：
- 解锁必须由用户明确确认，AI 不得自行解锁
- 解锁后必须重新走完整的验证流程（运行前验证→运行→运行后验证→自检验算），不能跳过任何环节
- 解锁原因、修改内容、影响范围必须记录在 AI 使用记录中

## 八、阶段门禁机制（新增）

> 每个阶段（S1-S6）全部步骤完成后，进入下一阶段前，必须运行 `scripts/阶段门禁检查.py` 验证本阶段产物完整性。此为技术强制机制，不可跳过。

### 8.1 门禁触发时机

每个阶段全部步骤完成时，自动触发门禁检查。门禁通过后才允许进入下一阶段。

### 8.2 门禁规则

| 检查项 | 门禁行为 |
|--------|----------|
| 应有产物缺失 | ❌ 门禁不通过，输出缺失文件清单 |
| 产物存在但无变更说明 | ❌ 门禁不通过，标记"格式不合规" |
| 产物存在但无隔离检查结论 | ❌ 门禁不通过，标记"微循环未执行" |
| 隔离检查结论结论为❌需修改 | ❌ 门禁不通过，标记"检查未通过" |
| 不通过 | ❌ 门禁不通过，标记"微循环质量不合格" |
| auto模式：决策日志缺失 | ❌ 门禁不通过，标记"决策日志不完整" |
| auto模式：hard_blocker未记录暂停 | ❌ 门禁不通过，标记"hard_blocker未暂停" |
| 全部通过 | ✅ 门禁通过，允许进入下一阶段 |

### 8.3 门禁流程

```
阶段全部步骤完成
  ↓
运行 阶段门禁检查.py --phase <当前阶段> --dir <项目目录> [--auto]
  ↓
门禁通过？
  ├─ ✅通过 → 输出【步骤暂停 ⏸】等待用户确认 → 进入下一阶段
  └─ ❌不通过 → 输出门禁报告（缺失清单+问题清单）→ 补全后重新检查
      └─ 连续3次不通过 → 升级为 user_choice_needed
```

### 8.4 各阶段特殊检查

| 阶段 | 额外检查项 |
|------|-----------|
| S2 | 最终建模计划.md 必须存在（锁定步骤） |
| S3 | 中间数据/自检验算.log + 结果摘要.md + 变量符号约定.md 必须存在 |
| S4 | S4A+S4B+S4C 共16个产物必须齐全 |
| S6 | 论文.docx + AI工具使用详情.pdf 必须存在 |

### 8.5 调用方式

```
python scripts/阶段门禁检查.py --phase S1 --dir <项目目录>
python scripts/阶段门禁检查.py --phase S1 --dir <项目目录> --auto
```

## 九、扩展指南

### 添加新执行流程

1. 确定流程名称和适用场景
2. 定义流程步骤和退出条件
3. 在本模块中增加新章节
4. 如涉及检查标准，同步更新 `检查模板库.md`
5. 如涉及产物格式，同步更新 `产物规范.md`

### 修改现有流程

1. 找到本模块中对应的流程定义
2. 修改执行步骤或退出条件
3. 所有使用该流程的阶段自动生效
