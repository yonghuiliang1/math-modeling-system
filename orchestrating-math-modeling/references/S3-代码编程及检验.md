## 流程摘要（每步强制执行的通用流程）

> 详细规则以 `references/流程控制规范.md` 为准（第二章 9 动作序列、第三章 暂停确认、第五章 微循环修改）。以下为每步执行的流程摘要，standard（手动）与 auto 模式均强制执行，不跳过。

### 每步 9 动作序列

1. **读取验证**：读取上一步产物 + 输出三要素摘要
2. **执行**：按步骤内容产出
3. **写入MD**：产物写入独立MD文件（含 `## 变更说明`），版本号 v1.0
4. **独立检查**（审查方物理隔离，硬性门禁）：主AI重读产物做初检（辅助参考）→ **spawn 隔离子Agent做终审**（Agent工具，subagent_type="general_purpose_task"，每次全新spawn，不复用产者上下文，审查范围白名单冷读，按三层标准逐项检查并给出具体证据）→ 隔离子Agent直接返回检查结论（【独立判决】+ 问题清单 + 优化建议），不产出独立隔离检查结论文件（含 `<!-- 由隔离检查Agent直写，未经生产转述 -->` 签名 + 【独立判决】）→ 结论不一致以隔离子Agent为准
5. **问题判定**：有问题 → 修改（版本递增 v1.0→v1.1）→ 再检查 → 收敛判定；无问题 → 通过
6. **技术验证**：运行 `python scripts/阶段门禁检查.py --phase S3 --dir <项目目录>`
7. **暂停**：输出【步骤暂停 ⏸】
8. **确认**：等待用户回复"继续"
9. **进入下一步**

### 暂停确认（每步开头强制执行）

```
【暂停确认】
- 上一步骤：步骤X_XXX
- 用户是否已回复"继续"：✅是 / ❌否
- 确认结论：可进入本步 / 等待用户回复
```

### 微循环技术验证 32 项（详见流程控制规范.md 5.5，以下为前16项摘要，完整32项详见原文）

1. 隔离检查结论记录存在性：每个产物 `## 变更说明` 含隔离检查结论记录
2. 重新读取确认：隔离检查结论中含 `重新读取确认` 且值为✅
3. 证据列完整性：证据列不为空、非纯"通过"二字、不命中空泛证据黑名单
4. 版本号分布：≥30%产物版本号>v1.0（产物<5时至少1个>v1.0）
5. 问题清单存在性：隔离检查结论中含 `问题清单` 段落
6. 结论字段：含 `结论` 字段且值为✅通过或❌需修改
7. 发现问题必须修改：问题清单非空但版本号仍为v1.0 → 判定"发现问题未修改"
8. 隔离子Agent复核：隔离检查结论中含隔离子Agent复核结论
9. 优化建议必填：含"优化建议"段落且至少1条实质建议（即使✅通过也必须给出）
10. 零问题附理由：问题清单为"无"时必须附具体理由，禁止只写"无"
11. 隔离子Agent独立产出：含"隔离子Agent问题清单"+"隔离子Agent优化建议"字段
12. 隔离子Agent发现而AI未发现 → 判定"检查走过场"，强制返工重查
13. 三板块A存在：隔离检查结论中含"原题对齐"板块输出，逐项证否或举证
14. 三板块B存在：隔离检查结论中含"数据核查"板块输出，逐数值追溯来源
15. 三板块C存在：含"优化建议"板块且至少1条具体定位实质建议，无"可提升"泛泛
16. 空话拦截：问题清单/证否项不得含"无/没问题/未发现问题/通过"空话而无实质证否理由

## 阶段概述

S3 是数学建模全流程的**循环"代码"端**，与 S2（建模计划）构成循环关系。目标：先执行数据清理与预处理（步骤3-0，循环外），再根据 S2 建模计划编写代码，经过运行前验证→运行→运行后验证→自检验算，产出真实数值与图表。验证不通过则区分"小修"（留在S3改代码）或"大改"（回S2改计划），循环迭代直到全部验证通过。

**【核心定位】**
- 步骤3-0 数据清理前置：读取原始数据→探查→清洗→质量验证→产出干净数据集（在循环之外，只做一次）
- S3 循环的"代码"端：写代码 → 运行前验证 → 运行 → 运行后验证 → 自检验算
- S2 是循环的"计划"端：产出计划 → 被 S3 验证 → 修正 → 收敛
- 两者循环直到验证通过，结果数据后才进入 S4（论文写作）

**【与 S2 的循环关系】**
```
【S2】建模计划(vN) → 【S3】代码实现(vN) → 【S3】运行前验证(含运行时间预估)
    ├─ 不通过 → 改代码(小修,留在S3) / 改计划(大改,回S2) → 回循环
    └─ 通过 → 【S3】运行代码（拆分A/B阶段）
        ├─ 阶段A：小数据运行+结果验证
        │   ├─ 不通过 → 改代码→重跑小数据(内部迭代,最多3轮,不写MD只记日志)
        │   └─ 通过 → 阶段B：全量运行(只跑一次)
        ├─ 【S3】运行后验证(含分问题独立运行)
        │   ├─ ④负向 → 回S2改计划 → 再改代码 → 回循环
        │   ├─ ⑤不对 → 改代码(只重跑受影响问题+依赖链)/回S2改计划 → 回循环
        │   └─ 都通过 → 【S3】自检验算 → 【S2】最终建模计划 → ✅确认(步骤3-5结果登记)
```

**【角色】** 你是严谨的科研编程工程师。本阶段把 S2 建模计划转化为可运行、可复核、结果真实的代码与支撑材料。

- **产物目录**: `S3_步骤产物/`
- **代码结构要求**: **分开写** — 每个问题独立 `问题X_求解.py` + `问题X_验证.py`（平铺在 `代码/` 下，无 main.py 主入口）+ `config.py`（路径基准唯一真相源）+ `requirements.txt` 版本固定。每个求解脚本末尾「三合一」输出（print 关键结果 + savefig 落盘 + `ZHANSHI` 开关控弹图）
- **主导技能**: `model-code-and-result-generator`（SKILL_006，生成代码脚手架与结果契约；主导步骤3-5.5 模型验证）
- **协同技能**: `data-cleaning-and-visualization`（SKILL_007，全量）、`scipilot-figure-skill`（SKILL_008，全量）、`nature-figure`（SKILL_009，仅模板）
- **横切支撑**: `context-memory-keeper`（SKILL_001，记录代码结果与运行参数）

## 关键约束

1. **步骤3-0数据清理前置**：数据清理在S2↔S3循环之外执行，只做一次。步骤3-1及后续步骤直接读取步骤3-0产出的干净数据集，不再混入数据清洗逻辑。如循环中发现数据问题需调整清洗策略，走独立的数据清理修正（不回S2）。
2. `model-code-and-result-generator` 原生输出目录为 `paper_output/results/`，须适配为用户逐步 MD 产物格式。
3. 代码采用**分开写结构 + config.py 路径基准**：每个问题独立 `问题X_求解.py`（求解 + 绘图 + 三合一输出一体化），结果数据保存到 `表格/`，图表保存到 `图片/`；所有路径经 `config.py` 统一解析（**禁止各写各的内联 `../` 相对路径**）。依赖按 `requirements.txt` 声明版本固定。
4. 图表职责分离：`scipilot-figure-skill` 先决策"画什么图"，`nature-figure` 按需执行"怎么画好看"（仅套模板）。**nature-figure 属英文期刊模板，套用后必须汉化适配**：图内坐标轴标签/图例/标题/注释/字体一律替换为中文，保持"图表全中文"硬性红线，不得把英文标签模板直接嵌入正文。
5. 公式编号采用全文连续编号，从 (1) 开始顺序递增，不按章节重置。
6. **循环修正原则**：验证不通过时，区分"小修"和"大改"。"小修"再分两类：**仅改图**（只改对应问题的绘图代码 + 重跑该问题脚本，秒级、不重跑求解）与**改求解逻辑**；"大改"（需改计划，回 S2 产出新计划再回 S3）。均留在 S3 产出 v(N+1)。
7. **as-built 优先原则**：循环退出后，S2 步骤2-3 最终建模计划必须与代码实际实现完全一致。若计划与代码不一致，以代码为准修正计划。
8. **结果摘要机制**：自检验算通过后，**自检验算通过后，结果数据作为最终结果存档**。后续 S4/S5/S6 直接从 `表格/` 读取引用。如需修改结果数据，走"改代码→重新运行→重新验证"流程。
9. 正文数值必须来自代码实际运行输出，严禁手算编造；任何数值先有代码 stdout 再写进 MD。
10. **约束贯穿核对（U1 升级）**：代码实现须对照 S1 题目约束清单逐条核对，确保代码逻辑不偏离题目硬性约束（如题目要求"平均分流"则代码必须实现均分逻辑）；任何偏离必须显式论证必要性并在运行前验证中说明。

### 细粒度暂停点（开发过程可视，问题1）

> 不改变「写代码 → 检查 → 小运行 → 全量 → 查结果」的顺序，只在每个问题的每个节点加**硬暂停**，让老公全程有刹车权和修改权。每个问题（3-1~3-4）按以下 5 个节点暂停：

| 节点 | 对应步骤 | 产出 | 暂停动作 |
|------|----------|------|---------|
| 1 写代码 | 3-1 | `问题X_求解.py` + `问题X_验证.py` | ⏸ 停，老公审代码、可当场改 |
| 2 运行前检查 | 3-2 | 结构覆盖检查结论 | ⏸ 停，看检查结论 |
| 3 小数据运行 | 3-3 阶段A | 小数据结果 + 方向判断 | ⏸ 停，看方向对不对 |
| 4 全量运行 | 3-3 阶段B | 全量结果 | ⏸ 停，看最终结果 |
| 5 结果检查 | 3-4 | 运行后验证结论 | ⏸ 停，确认通过 |

> 每个暂停点界面统一输出：本步产物 + 关键结果 + 检查结论 + `【步骤暂停 ⏸，等回复"继续"】`。问题一跑完 5 个暂停再进问题二，以此类推；全部问题跑完后，「自检 + 模型验证」也 ⏸。

### auto 模式（细粒度的刹车阀，防交互爆炸）

- 老公对某段放心 → 说「接下来自动」→ 跳过后续暂停一口气跑完，只在结尾汇总。
- 想重新把关 → 说「恢复暂停」→ 回到细粒度暂停。
- 默认状态 = 细粒度（最可控）；auto 是随时可切的可选项。auto 模式只跳过暂停动作，独立检查与模型验证标准不降低（详见流程控制规范.md 3.4）。

#### 数据预处理四道防线（总览）

数据预处理是建模质量的基石。步骤3-0 在原有探查→清洗→验证流程基础上，增加"四道防线"机制，层层把关：

| 防线 | 名称 | 核心目的 | 执行时机 |
|------|------|----------|----------|
| 防线1 | 数据特征画像 | 清洗前先"看懂"数据全貌，而非上来就套公式 | 清洗前必做 |
| 防线2 | 异常值多维交叉检测 | 不靠单一方法判定，至少2种方法一致才标记 | 清洗中 |
| 防线3 | 清洗决策透明化 | 每项操作可追溯，用户可逐条复核 | 清洗中 |
| 防线4 | 清洗后分布回检 | 确认清洗没有破坏数据整体特征 | 清洗后 |

> **核心原则**：让 AI 在动手清洗前，先"看懂"数据的全貌，而不是上来就套公式。只有至少 2 种方法都判定为异常的值，才标记为"疑似异常值"。只有 1 种方法判定的，标注"边缘异常值"但不自动处理，列入报告交用户决策。

#### ① 数据探查 + 防线1：数据特征画像

清洗前先生成一份"数据体检报告"，让 AI 先理解数据长什么样。读取赛题原始数据，执行以下画像检查：

| 画像项 | 具体内容 | 产出形式 |
|--------|----------|----------|
| 统计描述 | 每列的 count/mean/std/min/分位数/max | 表格 |
| 分布可视化 | 每个数值列的直方图+箱线图组合图 | 组合图 |
| 缺失值分布 | 缺失值热力图（哪些列缺失多、缺失是否有规律） | 热力图 |
| 相关性矩阵 | 数值列间相关系数热力图 | 热力图 |
| 唯一值检查 | 每列唯一值数量+列表（识别分类变量 vs 连续变量） | 表格 |

> **画像目的**：让 AI 在动手清洗前，先"看懂"数据的全貌，而不是上来就套公式。

同时完成基础数据探查：

| 探查项 | 检查内容 | 记录方式 |
|--------|----------|----------|
| 数据概览 | 数据文件数/行数/列数/字段名称 | 表格 |
| 缺失值检查 | 每列缺失值数量与占比 | 表格 |
| 异常值检查 | 数值列的统计描述（min/max/mean/std/分位数），标记疑似异常值 | 表格+分布图 |
| 数据类型检查 | 每列数据类型是否合理（数值/文本/日期） | 表格 |
| 数据分布检查 | 关键数值列的分布情况（正态/偏态/多峰） | 直方图 |

#### ② 数据清洗 + 防线2：异常值多维交叉检测 + 防线3：清洗决策透明化

根据探查结果执行清洗。异常值处理不靠单一方法判定，采用多重投票机制：

**防线2 — 异常值多维交叉检测（至少 2 种方法一致才标记）**

| 检测方法 | 适用场景 | 判定逻辑 |
|----------|----------|----------|
| 3σ法 | 正态分布数据 | 超出 μ±3σ 标记 |
| IQR法 | 偏态/非正态数据 | 超出 [Q1-1.5×IQR, Q3+1.5×IQR] 标记 |
| 箱线图法 | 可视化辅助 | 视觉确认异常点位置 |
| 业务逻辑法 | 结合题目背景 | 根据题目约束判断数据物理合理性 |

> **投票规则**：只有至少 2 种方法都判定为异常的值，才标记为"疑似异常值"。只有 1 种方法判定的，标注"边缘异常值"但不自动处理，列入报告交用户决策。

**清洗执行**：

| 清洗项 | 清洗策略 | 适用条件 |
|--------|----------|----------|
| 缺失值处理 | 删除/均值填充/中位数填充/插值/模型预测填充 | 缺失占比<5%删除，5%-30%填充，>30%标注并询问用户 |
| 异常值处理 | 截断/修正/标记保留/删除 | 根据多维交叉检测结果+业务逻辑决定 |
| 格式标准化 | 日期格式统一/数值精度统一/单位统一 | 全量执行 |
| 数据合并/拆分 | 多文件合并/一列拆多列/行列转置 | 按S2建模计划数据需求 |
| 数据类型转换 | 文本转数值/日期解析/分类编码 | 按模型输入要求 |

**防线3 — 清洗决策透明化（每项操作可追溯）**

每项清洗操作必须记录"被处理的原始数据"，让用户在暂停点可以逐条复核：

| 行号 | 列名 | 原始值 | 处理方式 | 处理理由 | 判定方法 |
|------|------|--------|----------|----------|----------|
| <行号> | <列名> | <原始值> | 删除/截断/修正/插值/填充 | <理由> | <判定方法组合> |

> **透明化要求**：暂停点时，AI 必须把清洗决策表展示给用户，用户确认后才进入步骤 3-1。每项清洗操作必须记录"操作内容+操作理由+影响范围+判定方法"，供论文"数据预处理"章节使用。

#### ③ 数据质量验证 + 防线4：清洗后分布回检

清洗后执行质量验证，同时独立检查确认清洗没有破坏数据整体特征：

**防线4 — 清洗后分布回检（防止清洗过度）**

| 回检项 | 通过标准 |
|--------|----------|
| 分布形态对比 | 清洗前后直方图形态一致（均值偏移<10%，标准差变化<15%） |
| 关键统计量 | 清洗前后 mean/median/std 变化幅度合理 |
| 行数损失 | 删除行数占比<10%（或>10%时有明确说明） |
| 相关性矩阵 | 清洗前后相关性结构未发生显著变化 |

**常规质量验证**：

| 验证项 | 通过标准 | 结果 |
|--------|----------|------|
| 缺失值清零 | 清洗后无未处理的缺失值（或已标注保留理由） | ✅/❌ |
| 异常值已处理 | 所有标记的异常值已处理或标注保留理由 | ✅/❌ |
| 数据类型正确 | 所有列数据类型符合模型输入要求 | ✅/❌ |
| 行数变化合理 | 清洗前后行数差异≤10%（或有明确说明） | ✅/❌ |
| 数据范围合理 | 数值列范围在业务逻辑合理区间内 | ✅/❌ |
| 指标方向统一 | 多指标综合评价/多目标类问题，正向（效益型）/负向（成本型）指标方向已统一并记录归一化方向（反向指标取负/取倒数），未出现方向混乱 | ✅/❌ |

        """
        分层比例采样
        参数：
            shuju: 原始数据 DataFrame
            fenceng_lie: 分层依据的列名（如'省份'、'月份'）
            bilv: 采样比例，默认10%
            zuixiao_hangshu: 每层最少保留行数，默认5
        返回：
            采样后的 DataFrame
        """
        caiyang_jieguo = shuju.groupby(fenceng_lie, group_keys=False).apply(
            lambda x: x.sample(n=max(int(len(x) * bilv), min(zuixiao_hangshu, len(x))),

        )

| ② | 每小问能算出答案 | 代码中是否存在对应每个子问题的计算功能（求解函数）？代码结构是否能产出预期输出（函数签名/返回值结构是否匹配）？ |
| ③ | 全面 | 是否遗漏了任何子问题或要求？验收标准中列出的输出是否都有对应代码？ |
| ④ | 运行时间预估（粗估） | 代码运行时间理论预估是否在可接受范围内？单问题是否超过4小时阈值？ |

#### 阶段A：小数据运行 + 结果验证

**A-1 分层比例采样**

使用步骤3-1编码规范中提供的 `fenceng_caiyang()` 函数，对干净数据执行分层比例采样：

| 步骤 | 内容 | 验证标准 |
|------|------|----------|
| 识别分组列 | 根据数据特征识别分层依据（类别列/时间列/数值分箱） | 分组列选择合理 |
| 分层采样 | 每层按比例采样（默认10%），每层最少保留5行 | 各层均有采样 |
| 采样后验证 | 各层覆盖率、各列完整性、分布相似度 | 采样前后均值/标准差偏差<15% |

**A-2 小数据运行**

将代码切换到小数据模式（`CESHI_MOSHI = True`），运行采样后的小数据集，记录：
- 运行是否成功（语法/逻辑错误检测）
- 实测运行时间（用于精估全量运行时间）

**A-3 运行时间实测精估（精估）**

用小数据实测耗时×数据量倍数推算全量运行时间：

| 精估结果 | 处理方式 |
|----------|----------|
| 精估 ≤4小时 | 进入阶段B全量运行 |
| 精估 >4小时 | 触发代码优化（第一级），优化后重新精估 |

> **超时处理策略（三级递进）**：
> - **第一级：代码优化**。优化原则——一切以答案服务。允许条件（4条全满足）：①答案仍优秀 ②覆盖场景不变 ③符合题意 ④每小问都能得出答案。禁止条件（任一满足即禁止）：✗答案变差 ✗覆盖场景减少 ✗不符合题意 ✗某小问无答案。优化迭代成本权衡：优化花费时间 < 优化节省的运行时间 → 值得；否则跳过。
> - **第二级：抽样运行**。优化后精估仍>4小时 → 用分层比例采样（与阶段A采样策略一致：全维度+分层次+分比例），计算采样比例使单问题运行≤4小时。抽样运行 → 结果验证（与小数据手算交叉验证）。论文中诚实说明采样比例、采样原因、采样策略。
> - **第三级：回S2换算法（hard_blocker）**。抽样后仍超4小时 → 回S2换算法（如精确算法→启发式算法，全局优化→局部优化+多起点）。

**优化手段参考清单**（第一级代码优化时可参考的手段及判定标准）：

| 类型 | 手段 | 判定标准 |
|------|------|----------|
| 计算加速 | 向量化运算（numpy替代循环） | 答案不变 → 允许 |
| 计算加速 | 并行计算（multiprocessing） | 答案不变 → 允许 |
| 计算加速 | 缓存中间结果 | 答案不变 → 允许 |
| 计算加速 | 换高效库（scipy替代手写） | 答案不变 → 允许 |
| 计算加速 | 矩阵运算替代逐元素循环 | 数学等价 → 允许 |
| 算法调整 | 迭代次数减少（如遗传算法1000→500代） | 答案仍优秀+覆盖不变+符合题意+每小问有答案 → 允许 |
| 算法调整 | 收敛阈值调整 | 答案仍优秀+覆盖不变+符合题意+每小问有答案 → 允许 |
| 禁止 | 删除约束条件 | 简化问题 → 禁止 |
| 禁止 | 删除部分场景 | 覆盖减少 → 禁止 |
| 禁止 | 跳过某小问 | 某小问无答案 → 禁止 |

> **优化迭代成本权衡**：用小数据模式估算优化效果（不用每轮全量测）。优化花费时间 < 优化节省的运行时间 → 值得；优化花费时间 ≥ 优化节省的运行时间 → 跳过。

**A-4 小数据结果验证（不止测"能不能跑"，还测"结果方向对不对"）**

| 验证项 | 验证内容 | 通过标准 |
|--------|----------|----------|
| 语法/逻辑检测 | 代码能否跑通，有无报错 | 无报错运行完成 |
| 结果方向验证 | 优化类问题：结果是否朝优化方向？预测类：趋势是否符合常识？ | 方向正确 |
| 结果量级验证 | 数值是否在合理范围内？（如不会出现负面积、超100%的概率） | 量级合理 |
| 各问衔接验证 | 前一问的输出传入后一问，数值是否正确流转？ | 数据流转无异常 |
| 边界触发检查 | 采样数据是否触发了所有分支逻辑？（如不同类别都跑到了） | 分支覆盖完整 |
| 手算复核 | 如果采样数据≤20行，挑2-3行手算关键结果 | 手算值与代码输出一致 |

#### 🔴 红队审查②：物理常识检验（Phase A 通过后、Phase B 前，硬性门禁）

> **时机**：Phase A 全部验证通过后、**进入 Phase B 全量运行之前**。此时小数据结果已出，是**最早能看到"数字符不符合现实"的窗口**——在全量运行前抓住量级/趋势/题意级别的硬伤，成本最低。

> **角色切换（关键）**：执行审查的 Agent 切换为"物理常识审查者"，**不看代码对不对，只看结果数字"像不像真的"**。

> **审查维度（逐条回答，每条须给出"判定+证据"）**：

| 攻击维度 | 审查问题 | 判定标准 |
|---|---|---|
| A. 量级 | 结果数量级是否符合物理常识/现实预期？（如充满时间应是天/小时而非万年/秒） | 结果数量级与现实常识偏差>1个数量级即判不通过 |
| B. 趋势 | 调整输入参数后，结果变化方向是否合理？（如增大流量，充满时间应缩短） | 趋势方向反直觉或与物理规律矛盾即判不通过 |
| C. 边界 | 极端值处（最大/最小输入）结果是否仍合理？有无爆炸/归零/负值？ | 边界处结果不可解释即判不通过 |
| D. 题意 | 结果是否回答了题目问的问题？有没有"算了一堆但没回答题目"？ | 结果与题目要求的输出对不上即判不通过 |
| E. 自洽 | 不同问题/子问题之间的结果是否矛盾？（如Q1的总数≠Q2各部分之和） | 跨问题结果矛盾即判不通过 |

> **审查流程**：
> 1. 提取 Phase A 小数据运行结果（关键数值、趋势、边界值）
> 2. 逐条回答上表 5 个维度，每条给出**判定（通过/不通过）+ 具体证据**
> 3. 任一维度判不通过 → **禁止进入 Phase B**，回 Phase A 内部迭代修正
> 4. 全部通过 → 输出物理常识检验日志 `中间数据/run_vN_phycheck.log`（含5条判定+证据），方可进入 Phase B

- 论文每个核心数字 → 有支撑材料（代码/原始数据/脚本）对应
- `solve()` 独立复现论文核心数值
- 禁止只给结果不给来源；正文数字 = 代码运行输出，禁手改

#### 第三部分 · 误差·对比·情景 三项检验

| 检验 | 内容 | 产出 |
|------|------|------|
| 1 误差分析 | 绝对/相对/均方误差 + 误差变化曲线 + 误差来源（假设/参数/数据噪声）+ 对结论影响 | 误差表 + 曲线 |
| 2 对比实验 | 经典/简化模型同数据对照，横向证明优劣 | 对照图 + 表 |
| 3 情景分析 | 乐观/基准/保守等多情景求解，验证结论稳健性 | 情景曲线图 |

**执行顺序（一句话总览，直接作为本步骤流程）**：
```
量纲边界检查 → 结果量级核验 → 参数扰动稳定性测试 → 关键假设敏感性对照
→ 核心数字可代码复现回溯 → 误差分析 + 模型对比实验 + 多情景测试
→ 全部通过才算模型可靠
```

**验证总判定**：
- ✅ **全部通过** → 进入步骤3-6（变量符号约定）
- ⚠️ **部分通过** → 未通过的检验项记录为「已知风险项」，随模型验证结论进入 S4A（模型检验章节引用）与 S5 综合校验
- ❌ **核心检验未通过** → 回 S2↔S3 循环（改计划/改代码），重跑后重新验证

> 将模型验证过程与结论写入 `模型验证结论.md`。写完后告知我文件已生成。

## 横切规则

| 规则 | 执行方式 |
|------|---------|
| **AI辅助非决策** | 代码实现由AI辅助，但核心算法逻辑、参数设计由参赛队独立完成；验证不通过时的修正方向由用户决定 |
| **决策点停下列选项** | 步骤3-5自检验算完成后为暂停点；循环中验证不通过时，列出"小修vs大改"选项交用户决定 |
| **严禁编造** | 所有数值必须来自代码实际运行输出；偏差超阈值回退重跑，不得凭印象改数 |
| **可追溯** | `AI使用记录.md` 记录每步决策链与循环迭代历史；数值交叉验证流程确保数据可回溯 |
| **题意对齐** | 每步产物末尾附 `## 题意对齐校验` 段落；运行前验证①就是题意对齐检查 |
| **循环记录** | 每轮迭代记录改动内容、原因、影响范围、排除路径 |
| **结果摘要** | 自检验算通过后，结果摘要作为核心数值汇总登记；如需修改，走"改代码→重新运行→重新验证→更新结果摘要"流程 |
| **微循环检查（强制）** | 每步产物写入后由隔离子Agent冷读检查，不产出独立隔离检查结论文件，直接反馈问题清单+优化建议。Agent工具，subagent_type="general_purpose_task"。 |

### 数值交叉验证流程

1. 代码运行产出 stdout 与结果文件，作为唯一数值源。
2. 步骤3-3将数值写入 MD 时，逐项标注来源（对应代码输出位置）。
3. 步骤3-5以独立验算脚本复核，产出对比表（运行值 / 验算值 / 偏差 / 是否通过）。
4. 偏差超阈值则回退步骤3-1重跑，严禁凭印象修正 MD 数值。
5. 通过的数值进入 `context-memory-keeper` 登记为"已验证值"，供 S4 回溯引用。

**【步骤暂停 ⏸】** 步骤3-5自检验算完成后停止，向我汇报代码结果与自检结论，等我确认结果无误后再进入步骤3-6。

- 🔧 需要返工 → 回 S2↔S3 循环，指定修正方向
