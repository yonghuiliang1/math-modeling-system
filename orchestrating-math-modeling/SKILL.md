# 数学建模全流程编排器（v2.0 代码驱动版）

## 核心理念

**方案是跑出来的，不是设计出来的。数据是锁定后再写，不是写完再对。**

本编排器的核心创新是 S2(建模计划) 与 S3(代码) 之间的循环结构：建模计划驱动代码实现，代码运行结果反向修正建模计划，两者循环迭代直到结果验证通过，结果数据后才进入论文写作。从根源上解决"计划跑不通、代码改了数据对不上"的实战痛点。

S3 代码环节在此基础上叠加两项强化：①**细粒度暂停点**——每个问题按「写代码→运行前检查→小数据运行→全量运行→结果检查」5 个节点硬暂停，让用户全程可介入、随时刹车修改，不再黑盒"一口干到底"（配 auto 模式随时切换）；②**模型验证（步骤3-5.5）**——采用《检验》文档标准（四检：量纲边界/结果量级/参数稳定性/敏感性 + 核心数字可回溯 + 误差/对比/情景三项检验），对全量结果做系统化正式精检，保证模型可靠而不仅是"能跑通"。

## 何时使用

**使用本技能当：**
- 用户开始数学建模竞赛，需要从赛题分析到论文定稿的全流程编排
- 用户需要恢复中断的工作流（断点恢复）
- 用户不确定当前阶段应该调用哪个技能
- 用户想了解某个阶段有哪些技能可以协同
- 用户需要全自动一体化执行（丢入赛题直接产出论文，无暂停点，AI自决策）

**不使用本技能当：**
- 用户只需要执行单一技能的原子任务（直接调用对应技能）
- 用户只做论文格式检查（直接使用 math-modeling-review）
- 用户只做数据可视化（单一可视化任务，直接使用 scipilot-figure-skill 或 nature-figure，无需启动全流程编排）

## 输入/输出

**输入:**
- `赛题文档`: PDF/Word/文本 — 竞赛题目
- `附件数据`: 文件 — 赛题附件（如有）
- `当前阶段`: enum(S1~S6) — 恢复中断流程时指定
- `execution_mode`: enum(standard, auto) — 默认standard；当用户说"全自动"/"一体化"/"不用暂停"时设为auto
- `用户决策`: string — standard模式下各暂停点的用户选择；auto模式下AI自决策

**输出:**
- `论文.docx`: 最终竞赛论文
- `支撑材料/`: 源代码 + 数据 + 图表 + AI工具使用详情.pdf
- `S1_步骤产物/` ~ `S6_步骤产物/`: 6个文件夹共41+个MD产物文件
- `编排日志`: 每阶段技能调用记录与决策历史
- `决策日志`: auto模式下额外输出，记录所有AI自动决策（选择X方案+理由），供用户事后审查

**架构原则:** 用户生产提示词是唯一流程权威 → S2计划与S3代码循环迭代至结果锁定 → 结果数据后论文写作只引用不修改 → 任何技能产物必须经支撑层校验 → 经暂停点确认后才进入下一步。

> **执行模式**: standard（默认，每步暂停） / auto（全自动一体化，无暂停，AI自决策，详见 `references/流程控制规范.md` 第3.4节）。auto模式只跳过暂停+等待确认，独立检查（动作4，重新读取+三层叠加+隔离检查）绝不跳过。
>
> ⚠️ **auto模式技术强制（新增）**：auto模式保留，但增加以下技术强制机制，防止无人监督下检查走过场：
> - **阶段门禁检查.py**：每个阶段结束时强制检查产物完整性，不通过禁止进入下一阶段（替代暂停点的防跳步作用）
> - **决策日志验证**：阶段门禁检查时验证决策日志格式和完整性（每个决策点须有：决策内容+理由+备选方案）
> - **hard_blocker检查**：auto模式下若触发hard_blocker，须在产物中记录"已暂停等待用户确认"，阶段门禁检查时验证

## S2 ↔ S3 核心：建模计划与代码循环

### 设计动机

原流程 S2(建模计划) → S3(代码) 串行执行，存在根本矛盾：纸面方案在代码中跑不通，代码修改后数据与计划对不上。v2.0 将 S2 和 S3 设计为循环关系——S2 产出计划，S3 根据计划写代码并验证，验证不通过则回 S2 修正计划，两者循环迭代直到结果验证通过、结果摘要。

### 循环结构

```
┌──────────────────────────────────────────────────────┐
│           S2(建模计划) ↔ S3(代码) 循环                 │
│                                                       │
│  【S2】建模计划(vN)                                   │
│      ↓                                                │
│  【S3】代码实现(vN)                                   │
│      ├─ 代码内置：小数据开关+分层比例采样+--wenti参数   │
│      ↓                                                │
│  【S3】运行前验证                                      │
│    ①符合题意？②每小问能算出答案？③全面？               │
│    【加速层3】运行时间理论预估（4小时阈值，超时预警）     │
│      ├─ 不通过 → 改代码(小修,留在S3)                   │
│      │              / 改计划(大改,回S2)→回循环          │
│      └─ 通过 ↓                                        │
│  【S3】步骤3-3运行代码 ← 拆成两个阶段                   │
│    │                                                  │
│    ├─ 阶段A：小数据运行（分层比例采样10%）               │
│    │   ├─ 语法/逻辑检测+结果方向验证+各问衔接验证         │
│    │   │  +边界触发检查+手算复核                          │
│    │   ├─ 实测精估运行时间（小数据耗时×倍数推算全量）      │
│    │   └─ 不通过→改代码→重跑小数据（内部快速迭代,不写MD） │
│    │       ├─ 3轮内通过→进入阶段B                        │
│    │       └─ 3轮仍未通过→升级为user_choice_needed       │
│    │                                                  │
│    ├─【超时处理分支】精估>4h三级递进：                    │
│    │   ①代码优化(不降精度/不删减)→仍>4h                  │
│    │   ②分层比例抽样运行(交用户决策)→仍>4h               │
│    │   ③回S2换算法(hard_blocker)                         │
│    │                                                  │
│    └─ 阶段B：全量运行（只跑一次）→ 产出最终结果          │
│      ↓                                                │
│  【S3】运行后验证                                      │
│    ④答案正向/优于原题？⑤每小问数据对得上？             │
│    【加速层2】只重跑受影响问题（不全量重跑）              │
│      ├─ ④负向 → 回S2改计划→再改代码→回循环            │
│      ├─ ⑤不对 → 改代码(只重跑受影响问题+依赖链)         │
│      │              /回S2改计划→回循环                  │
│      └─ 都通过 ↓                                      │
│  【S3】自检验算（独立脚本复核+图表质量14项）             │
│      ↓                                                │
│  【S3】模型验证（步骤3-5.5 四检+可回溯+三项检验）        │
│      ↓                                                │
│  【S2】根据代码完善建模计划(最终版)                     │
│      ↓                                                │
│  🔒 结果数据 + 锁定计划，退出循环，进入S4              │
│  （结果载体：步骤3-5结果登记）                           │
└──────────────────────────────────────────────────────┘
```

### S2 步骤详解（建模计划）

| 步骤 | 产物 | 干了什么 | 暂停？ |
|------|------|----------|--------|
| 2-1 | `可行性与风险应对.md` | 可行性分析+风险识别→升级主方案+备选方案+应对策略+评委评分校验 | 是 |
| 2-2 | `建模计划_vN.md` | 基于S1初稿方案细化：公式草案、伪代码、数据流图、验收标准 | 是 |
| 2-3 | `最终建模计划.md` | 循环退出后，根据代码完善计划，与代码完全一致 | **是(锁定确认)** |

### S3 步骤详解（代码编程及检验）

| 步骤 | 产物 | 干了什么 | 暂停？ |
|------|------|----------|--------|
| 3-0 | `代码/数据/（干净数据集）` | 数据探查→清洗（缺失值/异常值/格式）→质量验证→产出干净数据集（循环外，只做一次），含四道防线（画像/多维检测/透明化/回检） | 是 |
| 3-1 | `代码/ 目录` | 根据S2计划写代码：**分开写**（`config.py` 路径基准唯一真相源 + `问题X_求解.py`(求解+绘图+三合一输出) + `问题X_验证.py` 平铺，无 main.py）+数据加载+分层比例采样+分问题独立运行架构+小数据开关+运行时三合一输出（ZHANSHI开关） | 是 |
| 3-2 | `中间数据/运行前验证.log` | ①符合题意？②每小问能算出答案？③全面？+运行时间理论预估（4小时阈值） | 是 |
| 3-3 | `表格/ + 图片/ + 中间数据/运行输出.log` | 拆分阶段A（小数据运行+结果验证）+阶段B（全量运行），含内部快速迭代 | 是 |
| 3-4 | `中间数据/运行后验证.log` | ④答案正向/优于原题？⑤每小问数据对得上？ | 是 |
| 3-5 | `中间数据/自检验算.log + 结果摘要.md` | 独立验算脚本复核结果+图表质量14项专项检查，偏差超阈值回退 | 是 |
| 3-5.5 | `模型验证结论.md` | 采用《检验》文档标准：四检（量纲边界/结果量级/参数稳定性/敏感性）+核心数字可回溯+三项检验（误差/对比/情景），全量结果正式精检 | 是 |
| 3-6 | `变量符号约定.md` | 全流程符号统一基准(符号×含义×单位×取值范围×来源步骤)，循环结束后基于最终代码锁定 | 否 |

### 验证体系

**运行前验证**（S3步骤3-2，代码写完、还没跑，查逻辑）：

| 序号 | 检查项 | 验什么 | 为什么运行前能查 | 不通过怎么办 |
|------|--------|--------|-----------------|-------------|
| ① | 符合题意 | 代码逻辑是否对应赛题要求 | 看代码结构即可判断 | 改代码(小修,留在S3)/改计划(大改,回S2) |
| ② | 每小问能算出答案 | 每个子问题是否都有对应的代码产出 | 看代码输出结构即可判断 | 补代码/回S2改计划 |
| ③ | 全面 | 是否遗漏了任何子问题或要求 | 逐条对照赛题原文 | 补全 |

**运行后验证**（S3步骤3-4，代码跑完、出了结果，查数据）：

| 序号 | 检查项 | 验什么 | 为什么必须运行后查 | 不通过怎么办 |
|------|--------|--------|-------------------|-------------|
| ④ | 答案正向/优于原题 | 结果是否朝正确方向（优化后比原来好，预测趋势符合常理） | 需要实际数值才能比较 | **回S2改计划→再改代码** |
| ⑤ | 每小问数据对得上 | 实际数值是否正确、交叉验证一致 | 需要实际数值才能验证 | 改代码/回S2改计划 |

### 结果摘要机制

结果摘要登记后：
- 结果摘要作为核心数值汇总基准，后续所有环节(S4/S5/S6)统一引用
- 建模计划如需修改，走"改计划→改代码→重新验证→更新结果摘要"流程
- 修改须记录原因和影响范围
- 结果载体：步骤3-5结果登记，作为结果摘要的物理载体
- S4引用规则：统一指向S3运行结果，禁止绕过代码实际输出直接编造数值
- 锁定记录写入 `结果摘要.md`

### 循环记录

每轮迭代记录以下内容，这些记录是论文"排除路径回顾"和"思考博弈感"的素材来源：
- 本轮改了什么（计划改了哪些 / 代码改了哪些）
- 为什么改（运行前验证不通过 / 运行后验证不通过 / 方向负向）
- 影响范围（涉及哪些子问题 / 哪些数据需要重算）
- 排除了什么（试过但走不通的方案，以及为什么走不通）

> 【补丁⑧】spawn 时首个指令采用统一《任务指令》：以"够不够国一"为标准**自由狠批**（哪里不行/为什么/怎么改），并对 4 类致命置疑（真增量量化/创新分布健康/文献区分度/物理机理级）**逐条用脑作答"通过/未通过+理由"**（指令全文见 检查模板库.md 6.1、判据见 流程控制规范.md 5.2.2）。4 类置疑答得好不好、通不通过由**检查者脑力+用户**定。**终止目标 = 步骤级国一**：检查者判定"当前产物已在其范围内达到可细化极限、可进入下一步"即算通过，单步产物不需证明整篇论文国一。
> 【补丁⑨】**复检独立触发**（根治"改完由生产者自判通过就停"）：版本每递增一次（vN→vN+1），**必须重新 spawn 一个全新隔离复检者独立 re-read 新版本**，由它**独立给出 `【独立判决】`（✅可停止 / ❌须返工）**——停止与否唯一判据之一（连同用户拍板），生产者无权代判；主AI 若在变更说明写"复检通过/三连通过"自判终止即被反向探针拦截。核心：**循环必须持续到第二个 AI 独立判"没问题"之后才停**，详见 流程控制规范.md 5.2.2。
> 【补丁⑩】**对账层强制考题（三查未完成绝不判 OK）**：隔离复检者判 `✅ 允许停止` 之前，**必须先完成对账三查**——对账①跨文档口径一致性（正文断言 × 已确认定稿/变更说明/③确认表三方硬对）/ 对账②物理分类复算（`判定式=代入数据=结果→归类`，无物理分类的文档产物可如实写 N/A）/ 对账③术语完备性（缩写/术语已定义且全文唯一）。**执行顺序先于补丁⑧ 4 类置疑**：先对账①②③ → 再审高度 → 最后独立判决；任一查缺 → 判"对账未完成，不得判 OK"，连1不通过、逼停。白名单(no_arith)产物**不豁免**（文档类最需对账①③），仅已登记豁免历史产物可跳过。落地见 检查模板库.md 6.1、流程控制规范.md 5.2.2/5.5。

## 执行步骤

### 启动流程

0. **初始化询问**: 技能被触发后，AI 首先向用户确认以下三项：
   ```
   你好！数学建模全流程编排器已启动，请提供以下信息：
   
   1. 赛题文档：请提供赛题PDF/Word/文本（拖入文件或粘贴路径）
   2. 附件数据：如有附件数据请一并提供（无则跳过）
   3. 执行模式：
      - standard（默认）：每步暂停，你确认后才继续。适合需要把控流程。
      - auto（全自动）：无暂停，AI自决策，一路执行到出论文。适合时间紧迫。
      （回复"全自动"即选auto，不指定则默认standard）
   ```
   - 用户提供赛题 → 进入步骤1
   - 用户未提供赛题 → 等待用户提供，不进入后续步骤
   - 用户未指定模式 → 默认standard
1. **加载启动必读3文件**: 加载 `SKILL.md`（本文件）+ `references/索引导航.md`（路由）+ `references/产物规范.md`（产物规范）。其余模块**按需加载**：进入某阶段时再读该阶段 reference 文件，遇到具体场景（暂停/微循环/检查/调用技能等）按索引导航.md 按需加载表读对应章节。
2. **初始化记忆中枢**: 调用 `context-memory-keeper` 创建/读取 `memoryskill.md`，记录赛题信息、执行模式与流程启动状态。
3. **流程预检**: 运行 `产物索引检查.py` 检查已有产物，判断是全新启动还是断点恢复。
4. **进入对应阶段**: 根据预检结果进入 S1~S6 的对应步骤。

### 每阶段执行模式

```
加载阶段编排文件(已内嵌提示词) → 初始化阶段上下文 → 逐步执行:
  每步(9动作序列):
    1. 读取验证：读取上一步产物 + 启动必读文件（索引导航.md + 产物规范.md）
       ├─【暂停确认】检查用户是否已回复"继续"
       └─【读取验证】读取上一步产物 + 输出三要素摘要
    2. 执行：按步骤内容产出
    3. 写入产物文件：将产物写入独立文件（含## 变更说明）
    4. 独立检查（先重读再检查，杜绝"自己查自己"）：
       4a. 重新读取：用Read工具重新读取刚写入的产物文件（强制！不能用产出上下文）
       4b. 检查执行：评委视角，三层叠加（通用+分类+专属），每项必须有证据
       4c. 隔离子Agent终审：spawn全新隔离子Agent冷读，直接返回结论（不产出独立_check.md文件）
    5. 问题判定：隔离检查发现问题？
       ├─ 是 → 进入微循环修改（修改→版本递增→重读→再检查，最多3轮）
       └─ 否 → 通过
    6. 技术验证：运行 `python scripts/阶段门禁检查.py --phase SX --dir <项目目录>` 验证微循环执行质量
    7.【暂停点⏸】输出暂停标记
       ├─ standard模式：输出暂停标记，停止生成
       └─ auto模式：跳过，不输出暂停标记，直接继续
    8. 等待用户回复"继续"
       ├─ standard模式：等待用户回复"继续"
       └─ auto模式：跳过，自动确认，AI自动触发下一步
    9. 进入下一步
  > 详细执行流程详见 `references/流程控制规范.md` 第二章
  每阶段结束:
    P1. 更新 context-memory-keeper
    P2. 运行 阶段门禁检查.py 验证产物完整性+微循环质量+（auto模式）决策日志
       ├─ ✅通过 → 输出【步骤暂停 ⏸】等待用户确认 → 进入下一阶段
       └─ ❌不通过 → 输出门禁报告（缺失清单+问题清单）→ 补全后重新检查
    P3. 确认后进入下一阶段
```

### S2 ↔ S3 循环执行模式（特殊）

```
进入循环前:
  【S3】0. 数据清理与预处理（循环外，只做一次）
          读取原始数据→探查→清洗（四道防线：画像/多维检测/透明化/回检）→质量验证→产出干净数据集
          【暂停点⏸】等用户确认清洗结果

进入循环:
  【S2】1. 基于S1初稿方案，编写建模计划(v1)
          【暂停点⏸】等用户确认计划
  【S3】2. 根据计划写代码(v1)（读取3-0产出的干净数据）
          代码内置：小数据开关+分层比例采样+分问题独立运行架构(--wenti参数)
  【S3】3.【运行前验证】①符合题意？②每小问能算出答案？③全面？
          +运行时间理论预估(4小时阈值，超时预警)
          - 不通过 → 小修改代码(留在S3)/大改回S2改计划 → 重编v(N+1)
  【S3】4.【步骤3-3运行代码】拆分两个阶段：
          阶段A：小数据运行（分层比例采样10%）
            ├─ 语法/逻辑检测+结果方向验证+各问衔接验证+边界触发检查+手算复核
            ├─ 实测精估运行时间（小数据耗时×倍数推算全量耗时）
            └─ 不通过→改代码→重跑小数据（内部快速迭代,不写MD只记日志,最多3轮）
                ├─ 3轮内通过→进入阶段B
                └─ 3轮仍未通过→升级为user_choice_needed

          【超时处理分支】精估>4h三级递进：
            ①代码优化(不降精度/不删减,一切以答案服务)→精估≤4h→进入阶段B
            ②优化后仍>4h→分层比例抽样运行(交用户决策,论文诚实说明)→进入阶段B
            ③抽样后仍>4h→回S2换算法(hard_blocker)

          阶段B：全量运行（只跑一次）→ 产出最终结果
  【S3】5.【运行后验证】④答案正向？⑤数据对得上？
          - ④负向 → 回S2改计划→再改代码 → 回到S2步骤1
          - ⑤不对 → 改代码(只重跑受影响问题+依赖链,不全量重跑)/回S2改计划 → 回到S3步骤2或S2步骤1
  【S3】6. 都通过 → 自检验算（独立脚本+图表质量14项检查）
          【暂停点⏸】等用户确认验算结果
  【S2】7. 根据代码完善建模计划(最终版)
          【暂停点⏸】锁定确认 — 用户拍板后结果数据+计划
  【S3】8. 变量符号约定（基于最终代码锁定符号体系）
  → 退出循环，进入S4
```

## 失败策略

> 失败处理遵循横切机制7（阻塞器分类与恢复），按3级分类处理。详见 `references/横切机制.md`。

| 失败点 | 阻塞类型 | 处理方式 |
|--------|----------|----------|
| 赛题文档缺失 | hard_blocker | 停止流程，提示用户提供赛题文件 |
| 上步产物缺失 | hard_blocker | 运行 `产物索引检查.py` 定位断点，回退到缺失步骤 |
| 技能调用失败 | limited_continue | 记录错误，尝试手动执行该技能核心任务，暂停交用户决策 |
| 独立检查未通过 | hard_blocker | 标记问题项，进入微循环修改→重读→再检查，3轮未通过则暂停交用户决策 |
| S3运行前验证不通过 | limited_continue | 改代码(小修,留在S3)/改计划(大改,回S2)→回循环 |
| S3运行后验证④负向 | limited_continue | 回S2改计划→再改代码→回循环 |
| S3运行后验证⑤数据不对 | limited_continue | 改代码(小修,留在S3)/回S2改计划(大改)→回循环 |
| 数值不一致(锁死后) | hard_blocker | 立即暂停，回溯到S2↔S3结果数据核对，严禁凭印象修改 |
| AI痕迹检出 | hard_blocker | 边写边查即时修复; 深层: 脚本扫描+修改动作+Gate 4.5门禁拦截 |
| 用户拒绝确认 | user_choice_needed | 停在暂停点，按用户指示返工或调整 |
| 文献暂未找到 | limited_continue | 标注 needs_source，继续写作，后续补充 |
| 图片缺失 | limited_continue | 占位标注，继续组装，后续补图 |
| 遇到图片需识别但当前模型不支持 | user_choice_needed | 暂停并提醒用户切换模型 |
| 代码运行超时(单问题>4小时) | limited_continue | 触发代码优化（不降精度/不删减） |
| 优化后仍超时 | user_choice_needed | 分层比例抽样运行（论文诚实说明） |
| 抽样后仍超时 | hard_blocker | 回S2换算法 |

## 断点恢复

1. 运行 `产物索引检查.py` 扫描 `S1_步骤产物/` ~ `S6_步骤产物/` 目录
2. 对比应有文件清单
3. 缺失项即为断点，从缺失的第一个文件对应步骤恢复
4. **S2↔S3循环中断恢复**: 检查循环记录，定位当前迭代版本号和所在阶段(S2或S3)，从对应步骤恢复
5. 读取 `context-memory-keeper` 的 `memoryskill.md` 获取上下文
6. **上下文压缩后恢复（新增）**: 先读 `references/索引导航.md` 定位当前阶段与入口文件 → 读最近一个已完成步骤的产物MD文件，从【上下文衔接】字段获取"前面关键点 + 下一步入口" → 按"下一步入口"指定的文件章节读取完整规则 → 输出【读取验证】后继续
7. 普通断点恢复：读取最近一个已完成步骤的产物MD文件，输出【读取验证】后继续

## 冲突解决规则

| 冲突对 | 解决规则 | 优先级 |
|--------|----------|--------|
| orchestrator vs 用户提示词 | 用户流程权威，orchestrator仅复用脚本 | 用户 > orchestrator |
| 建模计划 vs 代码结果 | **代码结果为准，计划反向修正** | 代码 > 计划 |
| paper-formal-writer vs micro-unit | formal-writer主导，micro-unit仅加速格式化段落 | formal-writer > micro-unit |
| nature vs scipilot | scipilot决策"画什么"，nature执行"怎么画" | scipilot(决策) > nature(执行) |
| auditor vs review | 互补并行：auditor查数据/逻辑，review查格式/措辞 | 互补，无冲突 |
| formal-writer vs chinese-thesis | formal-writer主导CUMCM写作，chinese-thesis的AIGC治理模块强制启用(非可选) | formal-writer(写作) > chinese-thesis(AIGC治理强制) |
